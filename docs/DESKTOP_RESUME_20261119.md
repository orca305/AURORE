## 현재 실행 상태

- 법령/시행령/시행규칙 34개, 조문·부칙 항목 8,136개, 마이그레이션 31개 보존.

- SSH는 자동 시작으로 TCP 2222에서 실행한다. DB와 AI의 직접 외부 노출은 하지 않았다.

재부팅 후 Windows의 동적 예약 범위 5433~5532가 DB 포트를 막아 Docker 시작이 실패했다. 사용자 Windows 관리자 확인 후 WinNAT을 잠시 중지하고 DB를 시작한 다음 WinNAT을 원상 복구했다. 5433 포트가 정상 연결됐으며 시스템의 영구 포트 범위/방화벽/DB 저장 위치는 변경하지 않았다. 재부팅 시 재발하지 않는다고 보장하지 않는다.

## 다음에 데스크탑 시작하기

local-dev/start-desktop.cmd를 실행한다. Docker/DB/Ollama/AI/백엔드/화면의 준비 상태를 확인하고 꺼진 서비스를 시작하도록 구성했다. 데스크탑 전용이며 노트북에서 원격 연결을 대신해 실행하는 파일은 아니다.

이미 실행 중인 서비스에서는 재시작하지 않는다. 실제 가동 상태에서 다시 실행해 PID가 바뀌지 않는 것까지 확인했다. 이번 복구에서 서비스는 추적 가능한 직접 실행 명령으로 시작했으며, 스크립트의 전체 콜드 부팅 경로를 별도로 재부팅해 시험한 것은 아니다. 로그는 Git 제외 local-dev/runtime에 남긴다. Windows 부팅 작업/새 자동 예약은 등록하지 않았다.

DB 포트 5433의 Windows 예약 오류가 다시 나면 local-dev/repair-db-port.ps1을 관리자 권한으로 실행한 뒤 시작 파일을 재실행한다. 이 복구는 WinNAT에 영향을 주므로 상시 자동 실행하지 않는다. 관리자 실행 확인은 Windows에서 직접 허용해야 한다. 기존 DB/볼륨을 초기화하거나 삭제하지 않는다.

## 근거 추출 안정성 개선

- 문서 인용 후보와 관련성 검토 모두 Ollama에 Pydantic JSON 스키마를 전달하고 think=false를 명시했다. 응답 후 원문 일치·출처 ID·중복 인용·검토 인덱스 검증은 계속 수행한다.
- 첫 3개 후보에서 관련 인용을 못 찾으면 다음 후보를 검토한다. 후보는 기존 SQL 상한 안의 최대 12개, 요청당 최대 3개이며 최대 4묶음이다. 추가 묶음 시작 예산은 30초이며 이미 진행 중인 요청에는 기존 제공자 타임아웃이 적용된다. 응답 구조 오류를 무시하거나 인용을 임의 보정하지 않는다.
- 로컬 AI 분석 결과로 일반 사용자 질문을 자동 차단하는 기능은 계속 비활성이다.

검증: Python 13개, 백엔드 단위 51개 통과. 실제 서비스 8001과 D의 공식 원문으로 13건을 순차 실행해 13/13 기대 출처·원문/근거 부족 기준을 통과했다. 평균 1.354초, P95 1.877초(이번 단일 실행). 직전 실행에서 보증금 질문은 RELEVANCE_GAP이었으며 추가 후보 검토로 해소됐다. 모델 출력을 온전히 신뢰하는 판정이 아니고 고정된 작은 회귀 자료의 결과다. 미사용 질의/다중 대화/동시성/법률 해설 정확도를 보장하지 않는다. 보고서는 Git 제외 backend/.eval-results/local-ai-20261119/rag-reboot-expanded.json에 저장했다.

## 회사 노트북에서 공유하는 구성

노트북의 앱/백엔드는 데스크탑의 같은 DB와 로컬 AI를 SSH 터널로 사용한다. 모델과 GPU 계산은 데스크탑에서 수행하므로 사용을 위해 노트북에 Ollama/대형 모델을 다시 설치할 필요가 없다. 노트북에서 앱을 직접 실행할 Node 등 개발 환경은 별도다.

| 노트북 접속 주소 | 터널 목적지 |
| --- | --- |
| DB 127.0.0.1:15433 | 데스크탑 127.0.0.1:5433, D의 같은 DB |
| AI http://127.0.0.1:18001 | 데스크탑 http://127.0.0.1:8001, 같은 Gemma 모델 |

1. 노트북에서 변경사항 확인 후 git pull --ff-only origin main.
2. 집 공유기에 외부 TCP 40222 → 192.168.0.3:2222 포트포워딩과 데스크탑 DHCP 주소 예약을 설정한다. 공인 IP/DDNS 및 이중 NAT 여부도 확인해야 한다. 공유기 설정 완료나 회사망 외부 접속 성공을 이번에 확인한 것은 아니다.
3. 노트북의 기존 SSH 개인키를 유지하고 아래 명령으로 터널을 연다. 집주소는 공인 IP 또는 DDNS 이름으로 바꾼다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\local-dev\connect-desktop.ps1 -HomeAddress 집주소
```

처음 표시되는 ED25519 서버 지문은 SHA256:kThdpzy6iWXnC8nGaAgyuw5WFqu1uVT0VA9mhC0JHkQ와 비교한다. 터널 창은 사용 중 열어 둔다. 이 계정은 일반 명령 실행과 다른 목적지 연결이 막혀 있다. 현재 SSH PermitOpen도 127.0.0.1:5433과 127.0.0.1:8001임을 재확인했다.

4. 노트북 local-dev/.env의 DATABASE_URL은 데스크탑과 같은 DB 사용자/암호/DB 이름을 사용하고 호스트/포트는 127.0.0.1:15433으로 설정한다. AURORE_AI_URL=http://127.0.0.1:18001, AURORE_INTENT_CLASSIFY=0을 사용한다. 암호와 개인키는 Git이나 대화에 넣지 않는다. 코드 pull만으로 비밀 설정이나 터널이 자동 구성되지는 않는다.
5. 터널이 연결되면 노트북에서 AI 상태를 확인하고 로컬 앱의 법령 목록을 조회한다.

```powershell
Invoke-RestMethod http://127.0.0.1:18001/health
```

수집/모델 평가 등 일부 운영 도구는 여전히 데스크탑의 5433 개발 DB를 요구한다. 노트북 앱의 원격 DB 사용과 대량 수집 작업을 같은 동작으로 해석하지 않는다. 데스크탑이 켜져 있고 서비스가 가동 중이어야 하며, 회사 정책에서 외부 SSH가 허용돼야 한다. 전체 법령·판례·연혁 수집과 외부 GPT 자유서술 해설은 아직 완료 범위가 아니다.
