# 관심 법령·판례 사이트 내부 알림 — 2026-11-17

회원의 관심 법령에 공포·시행·원문 정정 알림을, 관심 판례에 원문 정정 알림을 제공한다. 이메일·문자·외부 푸시를 보내지 않으며 AI를 호출하지 않는다. 사이드바의 **알림**에서 목록·미확인 개수·개별/전체 읽음·종류/미확인 필터·10/20/50개 쿼리 페이징을 사용한다.

## 이벤트 기준

| 종류 | 기준 | 안내 범위 |
| --- | --- | --- |
| 공포 | legal_ver.prml_dt의 한국 시간 00:00 | 공포 자료가 DB에 공개되어 있는 경우 |
| 시행 | legal_ver.enfc_dt의 한국 시간 00:00 | 해당 시행본의 시행일 도래 |
| 일부 조문 시행 | 현재 판본의 ARTICLE 최상위 조문 중 버전과 다른 enfc_dt | 같은 시행본·같은 날짜는 한 알림으로 묶음 |
| 법령 원문 정정 | 같은 legal_ver에 새로 저장된 판본의 rgst_dttm | 이전 판본과 조문 번호·제목·본문·시행일의 실질 차이가 있을 때 |

| 판례 원문 정정 | 같은 legal_prec의 새 판본 반영 시각 | 사건번호·제목·법원·선고일·판시사항·판결요지·판결문에 실질 차이가 있을 때 |

알림은 법제처 전체의 실시간 변경이나 법률 적용 확정을 뜻하지 않는다. 기존 수집·관리자 반영 절차를 거쳐 **DB에 공개된 자료**만 사용한다. 시행일이 없는 자료는 날짜를 추정하지 않는다. 공포와 시행은 서로 다른 이벤트다. 원문 정정은 법률 개정과 구분한다.

정정 판정에서 공백·줄바꿈·NBSP 등 Unicode 공백만 다른 내용은 제외한다. 내용이 다른 판본은 이전/이후 revision ID를 고정하고 비교 화면에 연결한다. JSON 응답 형식만 다른 자료나 이미 본 원문은 수집 과정의 기존 처리와 이벤트 중복 제약으로 재알림하지 않는다. 공포·시행 알림의 시행본 링크는 현재 공개 원문을 보여 주며, 정정 비교 링크는 당시의 전후 판본을 지정한다.

## 구독·전달·읽음

- 활성 회원·활성 관심 등록 이후의 이벤트만 전달한다. 초 단위 정책상 같은 초의 등록/이벤트는 포함한다.
- 공포·시행은 실제 날짜 기준이므로 늦게 수집한 과거 공포 자료를 신규 공포처럼 보내지 않는다. 정정 시각은 공식 발표 시각을 추정하지 않고 저장 판본 반영 시각을 사용한다.
- 관심 해제 후 새 전달은 중단한다. 이미 받은 알림과 읽음 상태는 남긴다. 재등록 이후에도 회원·이벤트 UNIQUE로 이미 전달한 알림은 다시 만들지 않는다. 재등록 전 미전달 이벤트도 소급 전달하지 않는다.
- 삭제 법령·삭제 시행본·삭제 판례·현재 판본이 없는 판례·숨김 이벤트·숨김 개인 알림은 목록과 미확인 개수에서 제외한다. 계정 상태와 세션은 API 및 업무 트랜잭션에서 확인한다.
- 개별 읽음은 반복해도 최초 읽은 시각을 유지한다. **모두 읽음**은 조회 시 받은 최대 전달 ID까지 처리해 그 이후 도착한 알림을 자동으로 읽지 않는다. 종류 필터에 한정된 일괄 읽음이 아니라 수신함 전체 읽음이다.
- 제목·안내문·기준일·전후 판본은 이벤트 생성 시 고정한다. 법령명이나 현재 판본이 바뀌어도 기존 이벤트를 덮어쓰지 않는다. 관심 원문 본문·회원 대화·사건·첨부를 알림에 복사하지 않는다.

## 실행과 무결성

NestJS 시작 시 한 번, 실행 중 1분 간격으로 DB를 확인한다. 외부 API 호출은 하지 않는다. 서버가 꺼져 있으면 새 알림은 중단되고 다시 켜면 해당 시점까지의 미처리 이벤트를 점검한다. Windows 부팅 자동 기동을 추가한 것은 아니다.

한 트랜잭션에서 이벤트와 전달 기록을 처리한다. PostgreSQL 트랜잭션 점유로 중복 실행을 제어하고, 이벤트 키 UNIQUE·회원/이벤트 UNIQUE로 재시도 중복을 막는다. 한 번에 법령 이벤트 최대 100개·판례 이벤트 최대 100개·전달 최대 500개를 처리하며 나머지는 다음 회차에 계속한다. 현재 소규모 베타에서는 관심 회원 행을 ID 순서로 먼저 잠근 뒤 관심 행을 잠가 등록·해제와의 잠금 순서를 맞춘다. 회원 수가 커지면 이 스캔도 나눠야 한다.

실패하면 전체 트랜잭션을 되돌리고 다음 회차에 재시도한다. 로그는 `NOTIFICATION_SYNC_FAILED` 고정 코드만 남긴다. 알림 목록에는 현재 프로세스의 마지막 성공·실패 상태를 제공하고 실패 시 기존 알림을 유지하면서 지연 안내를 표시한다.

- `legal_chg_evt`: 법령·시행본 또는 판례 대상과 전후 판본·종류·범위·기준일·발생 시각·고정 안내문. CHECK로 두 대상 중 정확히 하나를 허용하고 복합 FK로 다른 법령/버전/판례의 판본 연결을 막는다.
- `user_ntf`: 회원별 전달·읽음·소프트 삭제. 이벤트의 원래 내용과 읽음 상태를 분리한다.
- 일반 물리 DELETE·CASCADE·DB 트리거를 추가하지 않았다. 회원 개인정보 파기 계획에는 관심 등록과 개인 알림 이력을 함께 포함해야 한다. 실제 파기 구현은 별도다.

## API

- `GET /notifications`: filter=ALL|UNREAD, kind=ALL|PROMULGATED|EFFECTIVE|CORRECTED, limit=10|20|50, offset 최대 100000.
- `GET /notifications/unread`: 현재 회원의 열람 가능한 미확인 개수.
- `POST /notifications/:id/read`: 현재 회원의 알림 읽음, 타인/없는 알림 404.
- `POST /notifications/read-all`: `{throughId:"조회에서 받은 최대 ID"}`. 요청의 회원 ID로 소유자를 바꿀 수 없다.

- GET /legals/precedents/:id/comparison: beforeRevisionId·afterRevisionId로 같은 공개 판례의 저장 판본을 지정한다. 없는/다른 판례 판본은 404, 합계 100만자를 초과하는 화면 비교는 400이다. 비교 화면은 /precedents/:id/compare이며 기존 형광펜 표시를 재사용한다.

변경은 동일 출처를 확인하는 Next.js 서버 액션을 거친다. 모든 회원 API는 no-store이며 GET은 알림이나 읽음 상태를 변경하지 않는다.

## 검증과 개발 DB

독립 임시 PostgreSQL DB에서 한국 시간 자정 직전·정각, 미래 시행 제외, 과거 공포 제외, 조문별 시행일 묶음, 정정 전후 고정, NBSP/공백만 바뀐 판본 제외, 구독 해제·재등록, 동시 생성·재시도 중복, 다른 회원 읽음 차단, 읽음 시각 멱등성, 일괄 읽음 이후 새 전달 보존, 필터·페이징, 삭제 자료 비노출과 조회 시 데이터 불변을 확인했다. 복합 FK의 잘못된 버전 연결도 거부한다.

실제 브라우저에서는 합성 회원·합성 법령으로 미확인 개수 갱신, 개별/전체 읽음, 미확인 필터, 고정 전후 판본 비교 화면 연결을 확인했다. 검증 화면에 표시된 날짜와 법령은 가상 자료이며 실제 공포·개정 소식이 아니다.

2026-11-17에 관심 판례의 정정 알림을 연결했다. 첫 수집은 정정으로 처리하지 않으며 새 판결 선고 알림과 구분한다. 독립 임시 DB에서 정정 전달·중복 방지·공백만 변경 제외·관심 등록 시점·해제 후 중단·다른 판례 연결 거부·삭제 판례 비노출·고정 판본 비교를 통과했다. 실 DB는 35개 테이블 전체 백업과 독립 복원 검증 후 20261117020000_precedent_notifications까지 적용했으며 기존 자료를 삭제하지 않았다.
