# 회원 탈퇴와 자료 정리 — 2026-11-17

## 사용 방법

마이페이지의 **탈퇴 안내 확인**에서 현재 이용 가능한 대화·사건·첨부·관심 항목·알림 건수를 확인한다. 현재 비밀번호와 안내 확인을 함께 제출하면 계정 접근을 종료하고 로그인 화면으로 이동한다. 마지막 활성 관리자 계정은 다른 활성 관리자가 있어야 탈퇴할 수 있다.

## 접수와 정리의 구분

1. 탈퇴 접수는 한 NestJS 트랜잭션으로 WITHDRAWN 전환·회원 소프트 삭제·모든 세션 철회·학습 활용 미동의 이력·미완료 AI 작업 취소·상태 변경 이력을 기록한다. 하나라도 실패하면 모두 되돌린다.
2. 요청한 회원의 신원은 세션에서 결정한다. 다른 회원 ID를 받지 않는다. 비밀번호는 기존 scrypt 검증과 요청 제한을 사용하고 트랜잭션에서 자격 증명과 현재 세션을 재확인한다. 비밀번호가 바뀌거나 계정이 차단·탈퇴됐으면 진행하지 않는다.
3. 새 요청은 즉시 인증 단계에서 차단한다. 이미 실행 중인 생성 호출은 끝날 수 있지만 lease_token 해제로 이후 결과 저장을 막는다. 외부 모델의 실행 자체를 취소하거나 이미 전달한 내용을 회수했다고 보장하지 않는다.
4. 계정의 하위 자료는 서버 시작 시와 이후 1분 간격으로 정리한다. 대화·메시지·사건·사실관계·첨부·관심 등록·개인 알림·역할은 소프트 삭제한다. 사건에는 DELETE_CASE 이력과 증가한 버전을 남긴다. 이미 삭제된 행의 삭제 시각은 덮어쓰지 않고, 삭제된 사건 밑에 남은 활성 사실관계도 정리한다.
5. 한 계정의 연결 자료 정리와 app_user.withdraw_arch_dttm 완료 표시도 하나의 트랜잭션이다. 중간 실패는 모두 되돌리고 다음 회차에 재시도한다. 이 시각은 **자료 소프트 삭제 완료**이며 개인정보 파기 완료 시각이 아니다.

탈퇴 접수와 하위 자료 정리는 잠금 순서를 분리한다. 접수 중에는 사건·대화 행을 잠그지 않는다. 정리 작업은 회원 SHARE → 사건 → 대화 순서로 잠가 이전 답변 완료의 소유자 검사와 충돌하지 않도록 한다. 작업기 간 중복은 PostgreSQL 트랜잭션 점유로 막는다. 관리자 상태 변경과 탈퇴는 같은 점유를 사용해 동시에 관리자 두 명이 탈퇴하는 경우에도 마지막 활성 관리자를 남긴다. 수동 DB/관리자 부트스트랩 변경까지 대신 보호하는 규칙은 아니다.

한 번에 대기 계정 10명을 살펴보고 계정별로 독립 처리한다. 계정 하나의 작업이 30초 트랜잭션을 초과할 만큼 커지면 더 작은 영속 배치로 나눠야 한다. PC·서버가 꺼져 있는 동안은 자료 정리가 중단되고 재기동 후 이어진다. 실패 로그는 원문·계정 식별자 없이 ACCOUNT_ARCHIVE_FAILED 코드만 기록한다.

## 실제 파기는 별도

본문·사건 이력·첨부 인용·인증 자료는 소프트 삭제 후에도 남는다. 일반 물리 DELETE, 본문 비우기, 비밀번호 덮어쓰기, 백업 사본 제거를 실행하는 기능은 추가하지 않았다. 아이디 UNIQUE도 유지하므로 실제 개인정보 파기 전 재가입·아이디 재사용은 허용되지 않는다.

관리자 **개인정보 보관**에는 자료 정리 대기/완료 계정, 회원 연결 이력, AI 사건 맥락 집계와 **파기 검토 계획**을 추가했다. 계획은 대상 수와 의존성만 읽는다. 계정·본문·사건 이력·첨부·관심/알림/동의/역할을 구분하고, 동시 변경 재검사·실행 증적·백업 복원 후 삭제/철회 재적용·학습 사본 전파를 남은 조건으로 표시한다. 원문과 회원 식별자는 반환하지 않는다. executionEnabled=false와 purgeImplemented=false를 유지한다.

실제 파기 수단과 실행 승인은 별도라는 기존 정책을 유지한다. 파기 구현·증적·백업/학습 전파가 끝나기 전에는 개인정보 처리 완료나 서비스 전체 운영 준비 완료로 표시하지 않는다.

## API와 브라우저

- GET /auth/withdrawal: 현재 회원의 활성 자료 건수만 조회한다. 읽기로 탈퇴나 자료 정리를 실행하지 않는다.
- POST /auth/withdrawal: currentPassword와 confirmed=true를 검증한다. 성공 응답은 202이며 withdrawn=true, archivePending=true, purgeCompleted=false를 반환한다.
- 인증 누락/만료/탈퇴 401, 잘못된 입력·비밀번호 400, 마지막 관리자 409, 요청 제한 429. 추가 회원 ID 필드는 거부한다.
- Next.js 서버 액션은 동일 출처를 확인한다. 성공을 확인한 경우에만 세션 쿠키를 만료시키고 완료 안내로 이동한다. 통신 실패나 401을 탈퇴 성공으로 표시하지 않는다.

## 검증과 DB 반영

독립 임시 PostgreSQL DB의 합성 자료로 본인 확인·추가 필드 거부·모든 세션 철회·로그인과 탈퇴 경합·동시 관리자 탈퇴·상태 이력/자료 정리의 실패 되돌림·재시도 멱등성·오래된 답변 완료와의 잠금 순서·취소된 lease의 결과 저장 차단을 검증했다. 타인 자료를 유지하고 본문·인용·비밀번호 해시를 실제 파기하지 않는 것도 확인했다.

기존 인증 보안·관리자 회원 관리·개인정보 집계 검사와 단위 검사 43개를 통과했다. 마이페이지·탈퇴 안내·관리자 파기 계획의 인증된 서버 렌더링 응답도 확인했다. 실제 브라우저 조작과 동일한 시각 검증은 아니다. AI 학습·추론은 실행하지 않았다.
