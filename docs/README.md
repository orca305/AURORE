## 다른 PC에서 이어 보기

처음 받는 PC에서는 `git clone https://github.com/orca305/AURORE.git` 후 `docs/README.md`를 연다. 기존 작업 폴더에서는 미커밋 변경을 먼저 확인하고 `git pull --ff-only origin main`으로 갱신한다. 충돌이나 분기가 있으면 강제 덮어쓰기 없이 검토한다. 설계 변경은 결정 기록과 검토 상태를 함께 갱신하여 커밋·푸시한다. GitHub에는 실제 상담·개인정보·비밀정보를 넣지 않는다.

## 구현 단계의 평가 안내

[AI 평가 실행 안내](AI_EVALUATION.md)는 후속 구현에서 사용하는 가상 평가 세트·노트북 회귀 검사·데스크탑 모델 평가·사람 검토 기준을 설명합니다. 이전 설계 승인 기록과 구분합니다.

[저장 원문 검색 점검 — 2026-11-16](SEARCH_REVIEW_20261116.md)은 조문·사건번호 검색과 인용 구간 선택의 개선·검증·한계를 기록합니다.

[AI 작업 처리 결과와 운영 진단](JOB_DIAGNOSTICS.md)은 관리자 화면의 처리 결과·오류 분류·집계 범위·본문 비노출 기준을 설명합니다.

[법령 수집 중단·재개 운영 안내](COLLECTION_RECOVERY.md)는 중복 실행 차단, 중단된 로컬 작업 복구, 관리자 상태 표시와 판례 수집의 남은 범위를 설명합니다.

[수집 예약·감시](COLLECTION_SCHEDULE.md)는 일일 예약, 재시도 한도, 실행기 기동·복구, 관리자 감시 화면을 설명합니다.

[개발 DB 백업·복구 검증](BACKUP_RESTORE.md)은 같은 시점의 백업과 독립 DB 복원, 내용·구조·번호 생성·실제 조회 검사를 설명합니다.
