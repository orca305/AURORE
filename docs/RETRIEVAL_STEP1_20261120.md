# 검색 개선 1단계 — 법령 우선순위·용어사전 연결 (2026-11-20)

법령 수집으로 DB가 약 1,000개에서 수천 개로 늘자 정확도가 떨어졌다(34개 기준 통과 19 → 16). 진단 도구 `backend/tools/diagnose-retrieval.mjs`로 실패 12건을 보니 정답 법령이 후보 12개 안에 있었던 것은 8건뿐이었고 대부분 1위가 아니었다.

## 변경 (`backend/src/chat/stored-evidence.ts`, `law-priority.ts`)

- 법령 종류 배율: 법률 1.0, 시행령 0.7, 시행규칙·훈령·예규·조례 0.4, 공단·공사·유공자·기념 등 특수 기관법 0.6.
- 핵심 생활법령(약 90개) 가점 +2.
- 용어사전 연결: 질문에 공개 용어(이름·동의어)가 있으면 그 용어 출처 법령 +8, 출처 조문 +16. 출처는 `src_ref`의 "법령명 제N조 조문 인용" 형식에서 읽는다. 사전을 읽지 못하면 가점 없이 검색한다.
- 가점은 질문 단어가 실제로 맞은 조문(base>0)에만 붙는다.
- 흔한 단어(처벌·계약·기준·방법·경우·요건·규정·가능·허용·법적·반환·조건·신청)는 가중치를 1로 낮춘다.

## 남은 문제

- 검색은 좋아졌지만 후보 중 AI 관련성 검토가 거절(`RELEVANCE_GAP`)하는 질문이 많다(음주운전은 도로교통법이 1위인데도 실패).
- 검색어가 일상어("단속기준")라 법률용어 조문("술에 취한 상태에서의 운전 금지")과 단어가 안 겹친다 → 검색어를 법률용어로 바꾸는 2단계, 의미 검색(임베딩) 필요.
- 엉뚱한 법령 인용이 늘었다(AI 검토가 느슨하게 승인). 검토 엄격도·재순위 검토 필요.

# 검색 개선 2단계 — 법률용어·법령 후보 힌트 (2026-11-20)

- AI 서버 `/intent/analyze`가 키워드 외에 `legal_terms`(조문에 나올 법령 용어 최대 5개)와 `law_names`(해당할 법령 후보 최대 3개)를 함께 낸다(호출 추가 없음, 필드는 선택이라 기존 출력도 유효).

- 평가 질문 `debt-collection`의 허용 법령에 채권의 공정한 추심에 관한 법률을 추가했다(실제로 해당하는 법).

# 검색 개선 4·5단계 — 의미(임베딩) 하이브리드 검색과 재순위 (2026-11-21)

## 측정 환경
수집 5,631개 완료 후(수집과 동시 실행 아님), 같은 합성 질문 50개(`EVAL_FIRST=50`), 로컬 Gemma(aurore-local:e4b), 단일 실행·소표본. 아래 수치는 매번 새로 측정했고 실행 간 편차가 있을 수 있다.

## 5단계 — 후보 풀 확대·결정적 재순위·병렬 검토 (효과 없음, 원인 확인)
- `stored-evidence.ts`: 어휘 검색 후보를 12개가 아니라 36개까지 가져온 뒤 `rerankRows`(질문의 법률용어가 조문 제목에 있으면 가점, 법령당 최대 개수 제한)로 상위만 남긴다. `answer.service.ts`: 3개씩 묶은 검토 묶음을 2개씩 동시에 호출하되 결과는 항상 앞 묶음을 우선한다(`AURORE_REVIEW_PARALLEL`).
- 결과(의미 검색 없이): 통과 30/50(기준선 33), 시간 변화 없음. Ollama가 동시 호출을 직렬 처리해 병렬 호출은 빨라지지 않았다. 차이 3건은 후보 순서 변화로 인한 변동이다.
- **원인**: 남은 실패 대부분은 AI가 거절한 것이 아니라 **정답 조문이 후보에 없는 것**이다(음주운전→도로교통법 제44조 "술에 취한 상태…"는 검색어 "음주운전"과 글자가 다름, 연장근로→근로기준법 제56조, 명예훼손→형법). 어휘 재순위로는 해결되지 않고 의미 검색이 필요하다.
- 검토 프롬프트(`document_answer.py`)와 "원문 글자 일치 검증·근거 없으면 답하지 않음" 원칙은 바꾸지 않았다.

## 4단계 — bge-m3 임베딩 하이브리드
- 모델: Ollama `bge-m3`(1.2GB, 사용자 허락으로 `ollama pull bge-m3`만 내려받음). 12GB VRAM에서 aurore-local:e4b와 함께 올라간다.
- 임베딩 파일(`D:\DATA\embeddings\bge-m3`, Git 제외, 203MB): 현행 조문 205,980개(법령별 최신 판본의 현행 개정본 ARTICLE), 입력 = 법령명 + 조문 제목·본문 앞 700자, int8 정규화 벡터 1024차원, 2,048개 단위 청크 파일 + `ids.json` + `manifest.json`. 생성: `backend/tools/embed-provisions.mjs`(재개 가능), 초당 약 85개, 약 41분. DB 스키마·확장 변경 없음.
- 검색(`vector-search.ts`, `stored-evidence.ts`): 질문+법률용어를 같은 모델로 임베딩해 내적 상위 40개를 구하고 어휘 후보와 RRF로 융합 → 법령 종류 배율(시행규칙 0.4 등) 적용 → 재순위 → 상위 12개를 AI가 검토한다. 법령당 최대 8개(4개로 두면 제44조가 잘려 8개로 완화). 명시적 조문·사건번호 질문에는 쓰지 않는다.
- 조문 안에서 질문과 뜻이 가장 가까운 항(원문 필드)을 임베딩 유사도로 먼저 고른다(`AURORE_SEMANTIC_CHUNK=0` 으로 끔). 인용문은 여전히 DB 공식 원문을 그대로 검증하며 임베딩은 순위용이다.
- 폴백: 임베딩 파일이 없거나 Ollama 임베딩 호출이 실패하면 어휘 검색만 쓴다. `AURORE_VECTOR_SEARCH=0` 으로 끌 수 있다. 파일 위치는 `AURORE_VECTOR_DIR`.

- 남은 9건 실패: 보증금 반환(deposit 계열)·상속포기·건축허가·교통사고 합의 등은 정답 조문이 후보에 있어도 AI 검토가 거절하거나(RELEVANCE_GAP) 다른 법령(주택도시기금법, 주택임대차보호법 제7조, 정보통신망법)을 고른다. 7.5B 로컬 모델의 관련성 검토가 한계다.
