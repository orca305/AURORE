# 판례 수집 중단·재개와 명시적 반영

2026-11-16 구현 기준. 이번 작업은 기존 판례 원문 조회·검증·저장 함수를 재사용한다. 새 DB 구조나 예약 작업은 추가하지 않았다.

## 수집할 목록

판례정보 일련번호 `ID`와 확인할 `caseNumber`로 목록을 작성한다. 사건번호만으로 서로 다른 판례를 합치지 않는다. 아래는 입력 형식 예시다.

```json
[
  {"ID": "239217", "caseNumber": "2023다258672"},
  {"ID": "193797", "caseNumber": "2005다4529"}
]
```

목록은 1~1000개이며 중복 ID와 임의 URL은 허용하지 않는다. 한 기록 폴더의 목록·순서는 처음 실행할 때 고정된다. 목록을 바꾸거나 같은 판례의 새 정정 원문을 수집하려면 새 기록 폴더를 사용한다. 실행 옵션은 최대 100건이며 기본은 20건이다. 이는 배치 처리 단위로, 화면 조회의 10/20/50 선택과는 별개다.

## 검색 결과에서 목록 자동 생성

판례 제목·본문 검색 또는 선고일 범위로 수집 목록을 만든다. [법제처 판례 목록 조회 가이드](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=precListGuide)의 검색 범위와 선고일 검색 변수를 사용한다. 선고일은 신규 등록일과 다르므로 이 명령을 신규 등록분만 발견하는 기능으로 해석하지 않는다.

```powershell
# 판례 제목에서 검색하고 선고일 범위로 제한
node --env-file=local-dev/.env --use-system-ca backend/tools/plan-precedent-collection.mjs local-dev/precedent-runs/selected-2019/input.json --query 보증금 --from 20190101 --to 20191231

# 위 목록을 이용해 별도 폴더에 원문 수집 시작
node --env-file=local-dev/.env --use-system-ca backend/tools/resume-precedent-collection.mjs local-dev/precedent-runs/selected-2019 --queue local-dev/precedent-runs/selected-2019/input.json

# 원문 수집 중단 후 완료하지 않은 판례부터 재개
node --env-file=local-dev/.env --use-system-ca backend/tools/resume-precedent-collection.mjs local-dev/precedent-runs/selected-2019
```

기본 검색 범위는 `--search title`이며 `--search body`로 본문을 검색할 수 있다. 검색어는 최대 200자이고, 검색어 없이 실행하려면 시작·종료 선고일을 모두 지정한다. `--from`과 `--to`는 유효한 YYYYMMDD 달력 날짜여야 한다.

100건씩 페이지를 읽고 판례 일련번호로 중복을 제거한다. 총 검색 결과가 1000건을 넘으면 자동 절단하지 않고 `SEARCH_TOO_BROAD`로 멈추므로 검색어 또는 기간을 좁힌다. 페이지 번호·건수 불일치, 전체 건수 변화, 반복 페이지, 동일 ID의 사건번호 불일치, 선고일 범위 이탈도 중단 사유다. API는 시점이 고정된 검색 스냅샷을 보장하지 않으므로 조회 중 자료 변경을 완벽하게 감지하는 기능은 아니다.

모든 페이지를 확인한 뒤 목록 파일을 한 번에 생성하며 기존 파일을 덮어쓰지 않는다. 결과가 0건이면 `saved: false`이고 파일을 만들지 않는다. 중간 조회 실패 시 부분 목록을 남기지 않으며 목록 생성부터 다시 실행한다. 이후 공식 원문 수집은 판례별 완료 기록을 이용해 재개한다. `input.json`은 입력 목록이고 같은 폴더의 `queue.json`은 수집기가 관리하는 고정 기록이므로 직접 덮어쓰지 않는다.

공식 검색 응답의 상세 링크에 OC가 포함될 수 있어 응답 전체를 파일로 저장하지 않는다. 판례 ID·사건번호·선고일만 선택한 뒤 검증하고, 최종 입력 파일에는 ID·사건번호만 남긴다. 인증값이 이 필드에 섞이면 거부한다. 이 명령은 판례 본문 수집이나 DB 반영을 실행하지 않는다.

2026-11-16 실제 API 검사에서 제목 검색·선고일 제한 19건과 제목 검색 696건(7페이지)의 목록 생성을 확인했다. 생성 파일의 ID·사건번호 형식과 인증값 미포함을 확인했으며 기록은 Git에서 제외된 `local-dev/precedent-runs` 아래에 보관했다. 실제 판례 본문 수집과 기존 DB 반영은 실행하지 않았다.

## 수집·상태 확인

저장소 루트에서 실행한다. 실제 수집에는 로컬 설정의 `MOLEG_OC`가 필요하다. 아래 `--status`는 외부 API와 DB를 호출하지 않는다.

```powershell
# 최초 수집: 목록 파일은 직접 작성
node --env-file=local-dev/.env backend/tools/resume-precedent-collection.mjs --queue local-dev/precedent-runs/input.json --limit 20

# 완료하지 못한 판례부터 이어서 수집
node --env-file=local-dev/.env backend/tools/resume-precedent-collection.mjs

# 상태 확인
node backend/tools/resume-precedent-collection.mjs --status

# 종료된 로컬 프로세스의 점유가 남은 경우, 확인 후 재개
node --env-file=local-dev/.env backend/tools/resume-precedent-collection.mjs --recover-lock
```

기본 기록 폴더는 `local-dev/precedent-runs`다. 첫 위치 인자로 다른 폴더를 지정할 수도 있다. 기록 폴더에는 고정 목록, 판례별 완료 기록, 해시로 식별하는 JSON 공식 원문, 실패 코드가 저장된다. 기본 기록 폴더는 Git에서 제외한다. 다른 위치를 쓰면 원문과 실행 기록을 Git에 포함하지 않도록 직접 관리한다.

같은 기록 폴더의 수집·반영은 동시에 실행하지 못한다. 실행 중인 프로세스의 점유는 복구 옵션으로도 빼앗지 않는다. 외부 기기·손상된 점유 기록도 자동 회수하지 않는다. 자세한 복구 조건은 [법령 수집 안내](COLLECTION_RECOVERY.md)의 점유 규칙과 같다.

매 실행마다 완료 원문의 해시·바이트 수·판례 ID·사건번호를 재검증한다. 이상이 있으면 덮어쓰지 않고 멈춘다. 첫 수집 실패에서 중지하며 다음 실행은 완료 건을 건너뛴다. 완료 기록 직전 중단되어 원문만 남은 경우 재조회할 수 있지만 같은 해시의 원문 파일을 중복 생성하지 않는다.

상태 출력은 완료·남은 건수, 다음 ID, 실행 상태, 고정 실패 코드만 제공한다. 실패는 원문 조회 `SOURCE_READ_FAILED`, 원문 검증 `SOURCE_INVALID`, 파일 저장 `SNAPSHOT_FAILED`로 구분한다. API 응답·원문 오류·인증정보는 실패 기록에 넣지 않는다. 수집 성공은 DB 반영 성공을 뜻하지 않는다.

## 확인한 자료만 DB 반영

별도 반영 명령에서만 DB에 저장한다. 전체 목록 수집 완료와 원문 검증이 필요하다. 정정 판례가 포함되어 있다면 기존 원문과 대조한 뒤 실행한다. 현재 반영 명령은 기존 노트북 개발 DB `127.0.0.1:5433/aurore_dev_check`만 허용한다.

```powershell
node --env-file=local-dev/.env backend/tools/apply-precedent-collection.mjs local-dev/precedent-runs --apply
```

기존 판례 가져오기와 같은 DB 작업 점유를 사용하고 목록 전체를 하나의 트랜잭션으로 반영한다. 한 건이라도 실패하면 전체를 되돌린다. DB 반영 직후 종료되어 재실행해도 동일 원문은 중복 반영하지 않는다. 기존 정정 이력·인용은 보존하며 소프트 삭제된 판례는 다시 게시하지 않는다. 반영 결과는 기존 관리 화면의 DB 집계와 판례 조회에 반영된다.

## 관리자 화면에서 검토

운영 관리의 **판례 수집 검토**에서 수집 묶음과 후보 목록을 확인한다. 묶음 목록과 후보 목록은 10/20/50개씩 조회한다. 원문을 수집한 판례는 현재 DB 원문과 수집 원문의 판시사항·판결요지·판결문을 나란히 볼 수 있다. 법제처 원문은 새 창으로 연다.

- 신규 판례, 기존 원문과 동일, 기존 원문과 다름, 삭제된 판례, 기존 판본 확인 필요를 구분한다. 동일 여부는 원문 해시 비교이며 의미상 법리 변경 판정은 아니다.
- 수집되지 않은 판례는 원문 대조를 열 수 없다. 원문이 변조되거나 기록에 문제가 있으면 해당 묶음을 확인 필요 상태로 표시하고 원문 조회를 거부한다.
- 삭제된 판례는 반영 금지로 표시하며 현재 DB 본문을 다시 게시하지 않는다.
- 관리자 권한과 유효한 세션을 모든 API에서 확인한다. 로컬 경로·원본 API JSON·점유 토큰은 응답에 넣지 않는다. HTML 원문은 화면에서 실행하지 않고 텍스트로 표시한다.
- 묶음·원문 조회는 읽기 전용이다. 원문 상세의 확인 항목에 동의하고 승인 버튼을 누르면 해당 판례를 명시적으로 반영한다. 수집 시작 버튼은 추가하지 않았다. CLI 반영 명령도 별도로 유지한다.

기본 저장소는 `local-dev/precedent-runs`이며, 필요하면 `AURORE_PRECEDENT_COLLECTION_ROOT`에 절대 경로를 설정한다. 루트 자체와 바로 아래 폴더의 `input.json` 또는 `queue.json`을 찾는다. 설정에 로컬 경로가 들어가더라도 화면에는 수집 묶음 번호만 표시한다. 루트 아래 100개 폴더까지만 지원하며, 더 많아지면 카탈로그 관리가 필요하다. 중첩된 하위 폴더는 자동 발견하지 않는다. 설정한 묶음 밖으로 연결되는 원문·기록 링크는 거부한다.

## 관리자 승인과 처리 이력

원문 상세에서 확인에 동의한 뒤 승인한다. 요청에는 UUID 처리 번호, 검토한 현재 원문 해시(신규 판례는 null), 수집 원문 해시가 포함된다. 승인 전 법제처에서 같은 판례를 재조회해 수집 원문과 바이트 해시가 일치하는지 확인한다. DB 잠금 안에서 관리자 권한·세션과 현재 판본을 다시 확인하고 기존 가져오기로 새 판본을 반영한다. 검토 후 다른 작업이 원문을 반영했거나 삭제되었으면 거부한다.

반영과 성공 이력은 하나의 DB 트랜잭션에 저장한다. 이력 저장까지 실패하면 판례와 원본 저장도 되돌린다. 실패 이력은 되돌리기 후 별도로 기록하며 원문 오류 대신 고정 분류만 저장한다. 같은 처리 번호·같은 관리자·같은 검토 내용의 재요청은 기존 결과를 반환한다. 다른 내용에 처리 번호를 재사용하면 충돌이다. 성공·실패 모두 최종 결과이므로 원인을 해결한 새 승인에는 새 처리 번호를 사용한다.

`legal_prec_ingest_hist`는 처리자·원문 해시·결과·판본·시각을 보존한다. 처리 이력 화면은 10/20/50개 단위로 조회하고 처리자 ID를 마스킹한다. 승인 버튼은 삭제되었거나 현재 판본을 확인하지 못한 판례에는 표시하지 않는다. 파일 구조나 원문 해시가 바뀌면 새로 대조해야 한다. 형식만 다른 원문과 과거에 수집한 원문은 기존 가져오기 정책에 따라 현재 판본을 유지할 수 있으므로 처리 사유를 확인한다.

합성 판례를 사용하는 별도 임시 PostgreSQL DB에서 공식 원문 변경, 권한 해제, 동시 승인·재전송, 현재 판본 변경, 성공 이력 저장 오류에 따른 전체 되돌리기를 검증한다. 실제 판례에 자동 승인을 실행하는 테스트가 아니다.

## 검증과 남은 범위

합성 원문·임시 폴더·임시 DB로 부분 완료 후 재개, 중복 실행 차단, 별도 프로세스 종료 후 복구, 비밀정보 제외, ID 불일치·원문 변조 거부, 전체 반영 되돌리기, 재반영 중복 방지를 검증했다. 실제 외부 API 수집과 기존 개발 DB 반영은 이번 검증에서 실행하지 않았다.

API 검색에서 목록을 자동 생성하는 기능은 구현했다. 관리자 원문 대조 화면도 구현했다. 주기적으로 새 판례를 발견하는 기능과 관리자 승인·DB 반영 화면과 처리 이력도 구현했다. 수집 예약·감시는 다음 작업이다. 법령의 날짜별 변경 수집과 판례의 선고일·신규 등록일을 같은 기준으로 취급하지 않는다.
