# 대화의 사건·첨부자료 선택 개선

2026-11-19. 집 데스크탑 원격 연결을 보류한 상태에서 일반 기능을 개선했다. 실제 D드라이브 자료나 DB 행은 변경하지 않았다. 스키마·마이그레이션 변경과 모델 실행도 없다.

## 화면과 동작

- 입력창 위에 이번 질문에 사용할 사건 사실관계 개수·법령 조회 기준일·첨부자료 이름·총 글자 수를 함께 표시한다. 자료마다 선택을 해제할 수 있고 사건 정보 사용도 따로 해제할 수 있다.
- 질문을 정상 저장한 뒤 선택을 해제하는 기존 정책을 유지한다. 사건을 대화에 연결하는 것과 사실관계를 이번 질문에 사용 승인하는 것은 별개다.
- 첨부자료 등록 성공 안내에 목록에서 이번 질문용 자료를 선택하는 다음 동작을 명시했다. 정제본을 등록하는 것만으로 자동 첨부하지 않는다.
- 첨부자료는 최대 3개·합계 12,000자 제한을 선택/전송 전에 확인한다. 자료별 실제 변환본 길이를 표시한다. 파일 원본 바이트 크기로 추정하지 않는다.
- 새 서버의 첨부 목록에 characterCount를 추가했다. 기존 소유권·삭제·만료 조건과 페이징을 유지하고 본문은 목록 응답에 넣지 않는다. 기존 서버가 이 필드를 반환하지 않으면 이미 권한이 확인되는 내용 조회 API로 실제 길이를 확인한다. 원문이나 길이를 확인하지 못하면 해당 선택을 완료하지 않는다.
- 서버는 전송·실행 시 원문 길이·소유권·삭제 여부를 계속 재검사한다. 화면의 제한 검사는 서버 검증을 대체하지 않는다.
- 변환본 검토 화면에 작성 길이를 표시하고 빈 내용 등록은 막는다. 저장 결과가 불확실할 때 동일 내용으로 다시 확인하는 버튼 문구를 구분한다.
- 선택한 첨부자료 요약을 목록과 별도로 유지해 페이지를 옮겨도 확인/해제할 수 있다. 목록 새로고침과 일부 통신 실패 안내를 보완했다. 이전 목록 응답이 새 조회를 덮어쓰지 않도록 요청 순서를 확인한다.
- 사건 연결 선택도 페이지를 옮긴 후 저장할 사건 제목을 계속 보여준다. 저장 중 표시와 통신 예외 안내를 추가했다.
- 사실관계 선택은 실제 서버의 제목·발생일·내용·줄바꿈·구분자를 포함해 길이를 계산한다. 기존의 항목당 임의 30자 추정을 제거했다. 선택한 정제본마다 해제할 수 있으며 8,000자 초과 안내를 표시한다. 보완 질문은 서버의 기존 추가 길이 검증을 계속 받는다.
- 날짜·검색·버튼은 줄바꿈과 최소 폭을 조정해 좁은 화면에 대응한다. 기존 테마 변수를 사용한다.

## 확인한 검증

- 서버 단위 53개 통과. 새 검사 2개는 변환본 실제 UTF-16 길이(이모지 포함), 목록 응답 본문 미노출, 다른 소유자 접근 거부를 확인한다.
- 선택 관련 Node 검사 2개 통과. 12,000자 경계·3개·중복·길이 누락을 검사하며, 사실관계 길이를 실제 서버 loadCaseContext의 결과와 대조한다. 8,000자 경계도 확인했다.
- 프런트/백엔드 빌드, 프런트 정적 검사 통과. 백엔드 정적 검사는 기존 경고 10개를 유지했다.
- 실제 공유 DB, 실제 파일 변환·모델 응답 및 브라우저 상호작용 전체를 이번 검사에서 실행하지 않았다. 화면 위치는 사용자 확인 범위이며 실제 서비스 재시작 후 자료 선택·등록·전송까지 확인하는 작업이 남아 있다.

재현: backend에서 pnpm build 및 pnpm test, frontend에서 pnpm build·pnpm lint·node --test tools/context-selection.test.mjs. Node의 TypeScript 모듈 감지 안내가 출력될 수 있으며 검사 실패가 아니다.

다음 일반 개발은 자료 선택 상태와 실패 안내를 다른 사건/첨부 화면에도 일관되게 적용하고 통합 흐름을 확인하는 것이다. 데스크탑 연결과 실제 데이터 검증은 별도 재개한다.
