# 의도 분류기 실제 학습·연결 점검 — 2026-11-17

기준 구현: 문자 TF-IDF(2~4그램) + 로지스틱 회귀, CPU. 생성형 AI나 GPU를 쓰지 않는다. 실사용자 대화·사건·첨부를 학습에 읽지 않으며, 저장소의 합성 질문 TSV만 사용한다.

## 현재 결과와 적용 상태

총 144개 질문: 학습 84개, 검증 24개, 테스트 36개. 시나리오별 4개 표현을 같은 분할에 묶었다. 테스트의 클래스별 표본은 각각 12개다. 초기 설계의 약 600개 자료 규모와 실제 대화 문맥 평가는 아직 충족하지 못했다.

| 항목 | 규칙 기준선 | 분류기 원래 라벨 | 낮은 점수 확인 질문 전환 후 |
| --- | ---: | ---: | ---: |
| 테스트 Macro F1 | 0.6473 | 0.8053 | 0.7012 |
| 테스트 법률 질문 재현율 | 58.33% | 83.33% | 58.33% |
| 법률 질문을 일반으로 보낸 수 | 5/12 | 1/12 | 0/12 |
| 확인 질문 비율 | 19.44% | 30.56% | 58.33% |

검증 자료만으로 고른 임계값은 0.5다. 검증 분기의 Macro F1은 0.7111, 법률 재현율은 75%다. 확인 질문 전환으로 법률→일반 오분류는 줄었지만 법률 질문 12개 중 5개를 확인 질문으로 보내 재현율이 낮다. 0/12 오분류를 무오류 보장으로 설명하지 않는다. 이 수치는 합성 소표본 결과이며 실제 사용자 성능이나 법률 답변 정확도가 아니다. score는 정답 확률로 표시하지 않는다.

**현 모델은 목표인 법률 재현율 95%·Macro F1 0.85에 미달한다. 따라서 실제 응답 경로 적용은 비활성이다.** API는 예측 결과만 반환하고 기존 대화 검색·예제 흐름을 유지한다. 검색·생성 호출 감소나 비용 절감은 측정하지 않았다.

오분류 검토에서는 중고 거래·상속·감정과 해고가 섞인 질문, 기술 도움·여행 일상, 상황이 생략된 권리 질문에서 혼동 또는 과도한 확인 질문 전환을 확인했다. 테스트 예제를 그대로 학습에 옮겨 점수를 올리지 않는다. 이후 조정하면 이 테스트 세트는 개발 회귀 자료로 취급하고 최종 평가에는 새 미사용 세트를 마련한다.

## 재현

저장소 루트에서 실행한다. 모델 파일은 pickle 기반 joblib 형식이므로 외부에서 받은 파일을 넣지 않는다. 고정된 비공개 `.intent-model` 폴더에 직접 학습한 산출물만 쓴다. 학습은 개발 DB에 접속하지 않는다.

```powershell
& ai-server/.venv/Scripts/python.exe -m pip install -r ai-server/requirements.txt
& ai-server/.venv/Scripts/python.exe ai-server/intent_lab/intent.py train --out ai-server/.intent-model
& ai-server/.venv/Scripts/python.exe -m unittest discover -s ai-server -p 'test_*.py'
```

학습 산출물은 `intent.joblib`와 `evaluation.json`이며 Git에서 제외한다. 보고서는 데이터 해시·라이브러리 버전·전처리·임계값·모델 파일 해시·혼동행렬·오분류를 연결한다. 현재 데이터 해시는 `6510379fc092001f46e9f9e78120d74f0cb2190e3e42c61ba62dee592e04ae6f`다. 학습 시간과 일괄 추론 시간은 해당 실행의 참고 값이며 서비스 p95 지연이나 비용 절감 수치가 아니다.

## API와 대화 연결

- `GET /intent/health`: 준비 상태·모델 해시·평가 기준 충족·응답 분기 활성 여부만 반환한다.
- `POST /intent/classify`: question 1~1000자, NFKC·공백 정규화 후 길이 재검사. 추가 필드를 거부한다. 라벨·점수·권장 경로·모델 해시·활성 여부를 반환하며 질문 본문을 응답에 복사하거나 저장하지 않는다.
- 모델은 최초 사용 때 읽고 프로세스 동안 고정한다. 재학습·검토 후 서버를 재시작해야 새 산출물을 읽는다. 파일 교체만으로 실행 중 모델을 자동 승격하지 않는다.
- 검증·테스트 모두 재현율 95%·Macro F1 0.85 이상, 법률→일반 오분류 0이어야 평가 기준을 충족한다. 이 조건도 운영 승인이나 충분한 표본을 뜻하지 않는다.
- 실제 분기는 추가로 `AURORE_INTENT_ENABLE_ROUTING=1`을 설정해야 열린다. 현재는 0으로 기동했으며, 지금 모델은 1로 설정해도 평가 미달 때문에 열리지 않는다.
- NestJS는 기존 규칙이 일반 검색으로 넘긴 질문에만 분류 API를 확인한다. 이미 진행 중인 임대차 사실 확인·승인 첨부·사건 문맥 흐름은 ML이 덮어쓰지 않는다.
- 응답 미활성·오류·시간 초과·잘못된 필드는 기존 저장 원문 검색으로 돌아간다. 명확한 법률 단서가 있는 질문은 GENERAL/CLARIFY 예측만으로 검색을 생략하지 않는다. 키워드 보조 방어가 모든 법률 질문을 검출하는 것은 아니다.
- 통신은 루프백 주소·리다이렉트 금지·1.5초 제한을 사용한다. 브라우저가 직접 부르는 공개 API가 아니다. 외부 배포 시 내부 서비스 인증·격리 검증은 별도 필요하다.

## 확인한 검사

Python 문서 추출·문서 답변·의도 API 검사 11개와 백엔드 검사 42개가 통과했다. 학습 산출물이 없는 새 체크아웃에서도 의도 검사가 임시 폴더에서 합성 자료로 학습해 재현된다. 기준 미달 때 활성 설정을 강제로 켜도 분기가 열리지 않는지, 손상·누락 모델·추가 입력 필드·정규화 길이 초과를 확인했다.

사건·첨부 통합 검사, 저장 원문 검색·인용·소유권·삭제 경합 검사, 기존 예제 대화와 평가 도구 검사도 통과했다. 새 API 호출을 문서 요청으로 가정하던 테스트용 서버는 경로를 구분하도록 보완했다. 실제 HTTP에서 모델 준비·기준 미달·분기 비활성을 확인했다. 이 검사는 실제 로컬 LLM 법률 답변 품질 검증을 대신하지 않는다.

다음은 독립 시나리오·문맥을 포함한 자료 확충, 검증 자료에서의 라우팅 정책 비교, 미사용 세트 평가다. 사용자 자료의 자동 학습·동의 변경·학습 철회·데이터셋 계보·운영 작업별 분류 버전 증적은 이번에 구현한 것으로 표시하지 않는다.

## 노트북 AI 작업 중단 후 운영 설정

사용자 요청에 따라 NestJS는 기본적으로 분류 API를 자동 호출하지 않는다. 데스크탑에서 AURORE_INTENT_CLASSIFY=1을 명시해야 호출하며, Python의 평가 기준과 AURORE_INTENT_ENABLE_ROUTING=1 조건은 별도로 유지한다. 따라서 노트북에서 일반 기능을 사용할 때 분류 추론을 자동 실행하지 않는다. 학습·성능 평가는 데스크탑에서 재개한다.
