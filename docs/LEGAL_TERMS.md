# 법률용어사전 — 2026-11-17

## 이번 구현

AI 없이 동작하는 저장·검색 사전이다. 공개 화면은 /terms, 관리 화면은 /admin/terms다. 사이드바와 관리자 메뉴에 각각 연결했다. 출처의 정의, 운영자가 작성한 쉬운 풀이, 동의어·약어, 출처 기관·원문 주소·조문/판본 기준을 구분한다.

용어·동의어 일부·정의·풀이를 검색하고 최신순/과거순과 10/20/50개 조회를 제공한다. 검색어의 %, _, 역슬래시는 패턴이 아니라 문자 그대로 취급한다. 정렬에는 변경 시각과 ID를 함께 사용한다. 공개 상세의 출처 원문은 새 창으로 연다.

## 등록·검토·공개·삭제

1. 관리자가 입력하면 임시 저장(DRAFT)한다. 비회원·일반 회원은 임시 저장이나 삭제 자료를 조회할 수 없다.
2. 출처 원문과 정의의 일치, 쉬운 풀이의 구분을 관리자가 확인한 뒤 공개(PUBLISHED)한다. AI나 프로그램이 원문 대조를 완료했다고 표시하지 않는다.
3. 공개 중인 용어를 수정하면 즉시 DRAFT로 전환하고 공개 검색에서 제외한다. 수정 전 내용을 공개한 상태로 유지하는 별도 초안 슬롯은 이번 범위에 없다. 입력 화면에서 저장 시 공개 중지를 안내한다.
4. 다시 검토한 뒤 공개한다. 각 등록·수정·공개·삭제는 버전을 증가시키고 변경 전후 내용과 처리자·시각을 보관한다.
5. 삭제는 소프트 삭제다. 관리자 삭제 필터와 변경 이력에서 과거 내용을 확인할 수 있다. 공유된 용어는 작성 관리자 탈퇴만으로 삭제하지 않는다.

## 저장과 무결성

- legal_term: 용어·정규화 이름·동의어 배열·정의·풀이·출처·공개 상태·버전·시각·소프트 삭제.
- legal_term_hist: 요청 UUID·용어 FK·처리자 FK·버전·작업·요청 해시·변경 전후 JSON·시각. 용어/버전 UNIQUE다.
- 활성 정규화 용어명은 부분 UNIQUE다. 이름은 NFC·소문자·공백 제외 기준으로 중복을 확인한다. 삭제 후 같은 이름으로 새 항목을 만들더라도 기존 이력은 남는다.
- 기본 범위는 활성 용어명 하나당 한 항목이다. 동형이의어·복수 출처 구조, 법령·조문 FK 연결, 자동 API 수집은 후속 확장이다. 출처의 적용 범위·판본은 현재 출처 기준 입력란과 URL로 기록한다.
- 일반 물리 DELETE·CASCADE·트리거를 추가하지 않았다. 관리자 탈퇴 시 처리자 식별 참조의 실제 파기 검토가 필요하며 개인정보 집계에 retainedTermActions를 추가했다. 이때 공용 용어 본문을 회원 개인 자료로 함께 제거하면 안 된다.

변경은 현재 관리자·세션·역할·공통코드를 트랜잭션 안에서 다시 확인한다. 용어 행 잠금과 기대 버전으로 동시 수정의 덮어쓰기를 막는다. UUID 요청 잠금·이력 PK와 정규화 이름 UNIQUE로 동일 요청 재시도와 중복 생성에 대응한다. 이력 저장에 실패하면 원문·공개 상태 변경도 되돌린다. 수정 후에도 예전 요청을 재전송하면 기존 처리 기록을 반환하며 새 변경을 만들지 않는다.

브라우저 변경은 동일 출처를 확인하는 서버 액션을 사용한다. 통신 결과가 불확실하면 입력 내용을 고정하고 같은 요청 번호·내용으로 재시도한다. 공개·삭제 확인 선택도 유지한다. 다른 내용에 같은 요청 번호를 사용하면 409다.

## 출처와 안전한 표시

출처는 인증정보가 없는 공공기관 .go.kr의 HTTPS 주소를 받는다. 사용자 정보·비표준 포트·DRF API 주소·OC/토큰 등 알려진 인증 쿼리는 거부한다. 임의 외부 주소를 서버가 가져오지는 않는다. 정의·풀이를 HTML로 실행하지 않고 일반 텍스트로 표시한다.

현재는 관리자가 직접 등록하는 방식이다. 초기 가상 정의를 운영 DB에 넣거나 확인하지 않은 정의를 자동 공개하지 않았다. 사전은 검토 후 공개한 용어가 생기기 전까지 빈 목록을 표시한다.

향후 수집 참고 문서는 [법령용어 목록 API](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsTrmListGuide), [법령용어 본문 API](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsTrmInfoGuide)다. API 수집·출처 스냅샷·정의 갱신 비교·대화 용어 연결은 이번 기본 사전과 구분한다. OCR·AI 학습·추론은 실행하지 않았다.

## API

- GET /terms: q, sort=newest|oldest, limit=10|20|50, offset<=100000. 공개·미삭제 자료만 반환한다.
- GET /terms/:id: 현재 공개 원문·풀이·출처·사전 버전.
- GET /admin/terms: 공개 조회 조건에 state=ALL|DRAFT|PUBLISHED|DELETED를 더한다.
- GET /admin/terms/:id: limit·offset으로 이력 페이징, historyRevision으로 해당 용어의 특정 변경 전후 내용 조회.
- POST /admin/terms: 입력 내용과 requestId로 임시 저장.
- POST /admin/terms/:id: 입력 내용·기대 revision·requestId로 수정하고 공개 중지.
- POST /admin/terms/:id/publish, /delete: 기대 revision·requestId·confirmed=true로 검토 후 공개/소프트 삭제.

응답은 no-store다. 공개 API는 임의 관리자 조회 조건을 거부하고, 관리자 API는 유효한 역할을 요구한다. 이력 조회는 해당 용어와 버전 조합으로 범위를 제한한다. 공개 API에 처리자·요청 해시·초안·이력을 포함하지 않는다.

## 검증과 DB 반영

독립 임시 PostgreSQL DB의 합성 자료로 권한·입력 형식·출처 제한·정규화 중복·임시 저장 비노출·공개 확인·수정 시 공개 중지·변경 전후 고정·동시 수정·동일 UUID 중복·롤백·소프트 삭제·삭제 후 재등록·공개 및 이력 페이징을 확인했다. 작성 관리자 탈퇴 후 공용 용어 유지와 이력의 파기 검토 집계도 확인했다. 공개 목록·상세와 관리자 목록·등록·검토/이력 화면의 서버 응답을 확인했다. 실제 위치·간격의 시각 검증은 사용자가 직접 확인하는 범위다.

단위 검사 43개·배포 빌드·정적 검사를 통과했다. 기존 백엔드 경고 10개는 유지되며 이 기능의 새 경고는 없다.

실제 개발 DB는 35개 테이블 전체 백업·독립 복원 검증 후 20261117040000_legal_terms까지 적용했다. 새 테이블 2개를 추가했고 실제 용어·이력은 초기 0개다. 기존 대화·사건·법령·판례는 변경하지 않았다. 합성 검증 자료는 임시 DB 안에서만 사용했다.
