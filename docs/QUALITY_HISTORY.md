# 품질 변화 기록

2026-11-20 ~ 11-22에 수행한 측정을 시간순으로 기록한다. 모든 수치는 `backend/tools/evaluate-explanations.mjs`로 재현할 수 있고, 결과 파일은 Git 밖(`backend/.eval-results/`)에 보관한다.

## 1. 측정 방법과 한계
- **질문**: 직접 만든 합성 질문(실제 사용자 질문 아님). 세트 4종 — 초기 50문항, 개발용 100문항, **홀드아웃 30문항**(튜닝에 쓰지 않은 질문), 새 문항 50개(그중 20개 사용).
- **통과**: 답변이 인용한 법령에 *기대 법령명*이 들어 있음(법령 이름 단위). 법과 무관한 질문은 근거 없이 보류해야 통과.
- **오인용**: 근거를 냈지만 기대 법령이 아님. **과잉 답변**: 법과 무관한 질문에 근거를 냄(전 측정에서 0, 단 등급 방식 1차 3건).
- **해설 성공**: 해설이 원문 대조 검증을 통과해 화면에 나간 건수(생성형 방식 이전의 지표).
- **한계**: 정답이 조문 단위가 아니고, 질문이 짧고 한 가지만 묻는 합성 질문이며, 표본이 작고(30~100), 법률 전문가 검토가 없다. 30문항 기준 1~2건 차이는 우연일 수 있다.

## 4. 측정 중 찾아 고친 버그
1. **원문 캐시가 처리 도중 필요한 법령을 밀어내 후보가 통째로 사라짐**: 한 질문에 필요한 원문이 캐시 크기(24개)보다 많으면 방금 불러온 민법이 같은 처리 안에서 밀려났다. 민법·형법 질문에서 국제사법·부정경쟁방지법이 대신 인용되던 원인. 질문별로 필요한 원문을 시작 시점에 확보하고, 캐시를 용량 기준으로 바꿔 해결(이전 측정에도 영향이 있었을 수 있음).
2. **병합 사건 판례 수집이 멈춤**: 목록 사건번호(`4287민상383`)와 본문 번호(`4287민상383-384-384`) 불일치 검사에 걸림 → 판례 일련번호 일치 + 병합 번호 형식만 허용.
3. **최신 판례 목록의 30~45%가 본문 조회 불가**: 새 사건번호 형식 항목을 목록 단계에서 제외.

## 5. 얻은 교훈
- 점수가 같아 보여도 **무엇이 바뀌었는지**(통과 vs 오인용 vs 억지 답)를 따로 봐야 한다. 통과를 늘리면 오인용이 느는 맞교환이 반복됐다.
- 큰 모델이 항상 낫지 않았다. 과제의 *구조*(후보 구성, 정답 기준)가 병목이면 모델 교체로 풀리지 않는다.
- 평가 지표가 법령 이름 단위라 같은 법령의 엉뚱한 조문은 못 잡는다. 조문 단위 정답과 법률 전문가 검토가 다음 단계다.
- 모델이 아는 지식을 막지 말고 **근거 표시와 검증으로 관리**하는 쪽이 사용자에게 도움이 됐다.
- 평가 도구만으로는 놓치는 문제가 있다. 실제 화면에서 직접 질문해 보다가 "형식 검사 거절 → 예전 방식 대체"를 발견했다. 평가 지표에 *어떤 경로로 응답했는지*(생성형/예전 방식)를 함께 기록해야 한다.
