# 법제처 법률용어 자동 수집

2026-11-17 구현. 관리자가 정의를 입력하는 대신 **운영 관리 → 용어사전 → 법제처에서 가져오기**에서 검색하고 최대 20개를 선택해 수집한다. 정의·용어·출처·원문 링크를 자동 채우며, DRAFT로 저장한다. 선택 수집이며 전체 사전의 주기적 수집은 아직 연결하지 않았다.

## 완료와 미완료

- 완료: 실제 API 검색/상세, 출처별 초안 저장, 원본 증거와 해시, 재수집 비교, 이력, 권한 확인, 공개 전 검토 화면.
- 미완료: AI 쉬운 풀이 생성, 모델 학습·추론 연결, 자동 품질 판정·자동 공개. AI가 작성했다고 표시하지 않는다. 노트북에서는 모델을 실행하지 않는다. OCR도 추후 연결한다.
- 공식 정의는 API 원문, 쉬운 풀이는 별도 필드다. 직접 수동 등록은 보조 기능으로 남아 있다.

## 수집 규칙

API target=lstrm을 사용한다. 목록의 법령용어ID가 쉼표로 여러 개 묶여 올 수 있어 ID별로 펼친다. 총 검색 건수·페이지당 개수는 법제처의 묶음 기준이며 화면의 실제 후보 수가 더 많을 수 있다. 같은 이름이라도 출처별 의미를 합치지 않는다. 상세는 이름 대신 정확한 trmSeqs 번호로 조회하며, 배열 응답은 ID 위치에 맞춰 검증한다.

검색 목록에는 있지만 상세가 없는 용어도 실제 확인했다. 해당 건은 실패로 표시하고 나머지는 계속 수집한다. 다른 용어의 정의로 대체하지 않는다. 불명확한 출처·길이 초과·잘못된 형식도 실패로 처리한다.

- 원본 src_snapshot: src_cd=MOLEG_TERM, src_key=용어 번호, 원문 JSON과 SHA-256. 공식 공개자료이며 사용자 첨부나 상담 자료가 아니다.
- legal_term: src_cd/src_key 고유 조합, 원문 snapshot FK, 내용 비교 해시. 같은 수동 용어와 공존 가능하다. 삭제된 출처 ID도 재사용하지 않는다.
- legal_term_hist: IMPORT 동작과 원문 snapshot FK를 기록하고 기존 이력을 보존한다. 후속 수동 변경 이력도 해당 출처 증거를 이어받는다.
- 재수집 내용이 같으면 저장·이력을 늘리지 않는다. 공백·줄바꿈만 다른 경우도 내용 변경에서 제외한다.
- 공식 정의가 바뀌면 새 초안으로 전환하며 기존 쉬운 풀이는 비운다. 운영자가 더한 동의어는 유지한다.
- 용어·정의·출처를 직접 수정했다면 재수집이 덮어쓰지 않고 확인 필요로 표시한다. 동의어·쉬운 풀이만 추가한 경우에는 이 보호에 해당하지 않는다.
- 소프트 삭제한 용어는 자동 복구하지 않는다. 공개·수정 중 동시 재수집은 기대 버전을 비교해 충돌을 표시한다.

## 요청과 보안

GET /admin/terms/sources?q=...&limit=10|20|50&page=1&sort=newest|oldest
POST /admin/terms/import: items=[{sourceId,requestId(UUIDv4)}], confirmed=true. 최대 20개이며 ID·요청 번호 중복을 거부한다.

관리자 확인은 외부 요청 전과 저장 직전에 수행한다. 성공한 변경은 요청 UUID·처리자·요청 해시로 재시도 중복을 막는다. 항목별 저장은 원본·용어·이력을 하나의 트랜잭션으로 처리한다. 실패 건은 결과에 개별 표시한다. 한 프로세스에서 한 배치만 실행하며 요청 시작 간격 500ms, 응답당 8초·1MiB 제한, 한 배치 약 55초 이후 나머지는 재시도 대상으로 돌린다. 여러 인스턴스 운영 전에는 API 호출량 제한을 공유 저장소로 옮겨야 한다.

API 인증값은 서버 설정에서만 사용한다. 검색 응답의 인증값 포함 상세 API 주소는 저장하거나 브라우저로 전달하지 않는다. 원문 링크는 고정된 국가법령정보센터 공개 주소와 검증한 번호로 구성한다. 상세 원본에 인증값이 섞이면 저장을 거부한다. 리다이렉트는 따르지 않고 오류에도 요청 URL·응답 원문을 노출하지 않는다. Windows 인증서가 필요한 환경에서는 Node의 시스템 인증서 옵션을 사용하며 TLS 검증을 끄지 않는다.

## 검증 및 반영

임시 DB에서 신규 수집·같은 이름의 다른 출처·UUID 재시도·다른 관리자 요청 충돌·변경 원문 초안 전환·수동 수정 보호·삭제 보존·일부 실패 후 계속·원본/이력 동시 롤백·조회 중 권한 철회를 검증했다. HTTP 경계 테스트에서 묶음 ID·인증값이 담긴 검색 링크 제거·상세 원문 해시·잘못된 UTF-8·크기 제한을 검증한다.

실제 API 읽기 확인: 보증금 검색 30개 묶음, 첫 10개 묶음을 펼치면 11개 후보. 관리보증금(5482926), 주거지원보증금(4924945/5482917)의 정확한 상세를 조회해 서로 다른 출처·정의를 확인했다. API 응답은 바뀔 수 있는 검증 당시 관측값이다. 실제 개발 DB에 검증용 자료나 임의 관리자 작업을 등록하지 않았다.

실제 DB 37개 테이블·500행의 백업 및 독립 복원 검증 후 20261117050000_term_source_import를 적용했다. 기존 자료를 덮어쓰지 않고 컬럼·제약조건만 추가/조정했다. 테이블 수는 그대로다.

검사: backend/tools/term-import.test.mjs, tools/moleg-terms.test.mjs, 기존 tools/legal-terms.test.mjs. AURORE_WEB_SMOKE=1로 수집 화면 서버 응답도 검증한다. 실제 간격·위치는 사용자가 직접 확인한다.

공식 안내: [용어 목록](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsTrmListGuide), [용어 본문](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsTrmInfoGuide).

최종 검증: 기존 서버 단위 43개, 용어사전/수집 임시 DB 통합 2개, 외부 응답 경계 3개와 인증된 수집 화면 서버 응답 통과. 개발 DB의 용어·공식 용어 원본은 각각 0개다. 프런트/백엔드 빌드·정적 검사 완료, 백엔드 기존 경고 10개 유지.
