# 관심 법령·판례 — 2026-11-17

회원은 법규·판례 검색에서 별표를 눌러 관심 항목을 등록·해제하고, 사이드바의 **관심 항목**에서 다시 확인한다. 이름·사건번호 검색, 법령/판례 구분, 페이지당 10/20/50개와 쿼리 기반 페이징을 제공한다. 선택 상태는 현재 페이지의 대상 ID를 한 번에 조회하며 자료별 추가 요청을 만들지 않는다. 비회원에게 저장 기능을 제공하지 않는다.

법령은 특정 시행본이 아닌 `legal` 자체에 등록한다. 판례는 `legal_prec` 자체에 등록하고 목록 제목은 현재 판본에서 읽는다. 삭제된 자료와 현재 판본이 없는 판례는 표시하지 않는다. 이전 제목이나 원문을 관심 테이블에 복사하지 않는다. 관심 등록 이후 저장 원문에 실질 변경이 반영되면 내부 알림으로 안내한다. 법률 적용 확정을 뜻하지 않는다.

## API와 저장

- `GET /bookmarks`: 현재 회원의 활성·열람 가능한 관심 항목만 검색·페이징한다. `kind=ALL|LEGAL|PREC`, `q` 최대 200자, `limit=10|20|50`, `offset` 최대 100000.
- `GET /bookmarks/state?kind=LEGAL|PREC&ids=...`: 현재 회원에 대해 대상 최대 50개의 상태를 조회한다. 타인의 등록 여부는 반환하지 않는다.
- `PUT /bookmarks/LEGAL|PREC/:targetId`: `{saved:true|false}`로 원하는 상태를 지정한다. 단순 반전 API를 쓰지 않아 같은 요청의 반복이 상태를 뒤집지 않는다. 사용자 ID를 요청으로 받지 않는다.
- 브라우저는 서버 액션을 사용하고 동일 출처와 서버 세션을 확인한다. API에서도 현재 회원·세션을 재검사하며 모든 응답은 캐시하지 않는다.

`user_bmark`는 회원·법령·판례 FK와 생성/변경/해제 시각을 보관한다. 대상 FK는 정확히 하나만 허용한다. 회원별 활성 법령/판례에 부분 UNIQUE를 적용한다. FK는 RESTRICT이며 일반 물리 DELETE나 CASCADE를 추가하지 않았다. 해제는 del_yn·del_dttm·del_id로 기록한다. 재등록은 새 행으로 만들어 이전 해제 이력을 남긴다. 시각은 초 단위 timestamptz(0)다.

변경은 회원 행을 잠가 같은 회원의 동시 요청을 직렬화하고, 현재 인증과 대상 공개 상태를 다시 확인한다. 등록 시 대상 행을 공유 잠가 삭제와의 경합을 제어한다. 타인 회원의 관심 행을 해제할 수 없으며, 해제 요청은 해당 회원·종류·대상의 활성 행에만 적용한다.

## 검증·DB 반영

독립 임시 PostgreSQL DB에서 미인증·비회원 차단, 소유권, 사용자 ID 위조, 5개 동시 중복 등록, 해제 반복·재등록 이력, XOR·활성 UNIQUE·해제 메타데이터 CHECK, 삭제 자료 제외, 검색·페이징, 조회 시 데이터 불변을 확인했다. HTTP의 invalid ID·추가 필드·조회 개수와 과다 대상도 검사했다. 실제 브라우저에서는 합성 회원과 합성 법령·판례로 등록·해제·재등록·관심 목록을 확인했다.

```powershell
Set-Location C:\dev\easy-law-ai\backend
pnpm prisma:generate
pnpm build
node --env-file=../local-dev/.env --test tools/bookmarks.test.mjs
```

개발 DB는 변경 전 전체 백업·독립 DB 복원 검증 후 `20261117000000_user_bookmarks`를 적용했다. 기존 행을 삭제·초기화하지 않았고 기존 자료를 관심 항목으로 자동 등록하지 않았다. 새 테이블 반영 직후 관심 행은 0개였다. 최종 브라우저 검증 자료는 임시 DB에서만 사용했다.

## 남은 범위

관심 법령의 공포·시행·원문 정정 알림을 후속 구현했다. [알림 실행 기준](NOTIFICATIONS.md)을 따른다. 관심 판례의 원문 정정 알림도 같은 수신함에 연결했다. 회원 탈퇴·개인정보 파기 계획을 구현할 때 관심 항목과 해제 이력도 의존성에 포함해야 한다. 현재 접근은 인증·계정 상태로 차단되지만 실제 개인정보 파기가 완료된 기능은 아니다. 대량 자료에서의 검색 성능과 유지 이력 정리는 별도 운영 검증이 필요하다.

이 작업에서 AI 학습·성능 평가는 실행하지 않았다.
