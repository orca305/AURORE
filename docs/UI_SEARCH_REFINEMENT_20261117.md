# 검색·상단 계정·첨부 화면 수정 — 2026-11-17

- 공통 상단의 새로고침을 제거했다. 검색 초기화 옆에 회전 화살표 아이콘으로 배치한다. 계정·대화·비검색 관리자 화면에는 공통 새로고침을 넣지 않는다.
- 닉네임과 로그아웃을 각각 테두리·전체 호버 영역이 있는 버튼으로 분리했다. 알림은 사이드바에서 제거하고 닉네임 왼쪽 벨로 이동했다. 읽지 않은 알림이 있으면 벨 오른쪽 아래 빨간 숫자 배지를 표시한다. 화면 이동·읽음 변경과 1분 확인으로 개수를 갱신한다.
- 검색 행의 입력·선택·버튼 높이를 맞추고 초기화/새로고침을 묶어 좁은 화면에서 줄바꿈하도록 했다. 사건의 관련 날짜 제목과 선택 안내를 한 줄에 묶어 날짜 입력 위치를 맞췄다.
- 첨부파일 패널을 대화 입력 폼 뒤로 옮겼다. 원본을 AI에 보내지 않고 변환·정보 정리·검토 후 등록하는 기존 절차를 유지한다.
- 법규·판례 검색 제목은 Unicode 문자 30개 이후 ...로 표시한다. 전체 제목은 마우스 안내·접근성 이름과 원문 화면에 유지한다. 관심 목록 제목도 같은 표시를 사용한다.

## 쿼리 정렬

최신순/과거순을 DB에서 처리하고 페이지 이동과 10/20/50개 선택에 유지한다. 초기화하면 정렬도 기본 최신순으로 돌아간다. API는 newest/oldest만 허용한다. 같은 시각의 행에는 ID를 함께 정렬해 페이징을 안정화한다.

| 화면 | 날짜 기준 |
| --- | --- |
| 법규 검색 | 저장 등록일 |
| 판례 검색 | 선고일 |
| 법령 시행본 | 시행일, 미상은 마지막 |
| 나의 사건 | 최근 수정일 |
| 관심 항목 | 관심 등록일 |
| 알림 | 수신 순서 |
| 관리자 회원 | 가입일 |
| 관리자 AI 작업 | 최근 변경일 |
| 관리자 작업 이력 | 처리 시각 |

조문 자체는 법 조문 순서, 대화 기록은 기존 최근 수정 순서를 유지한다. 의미 없는 최신/과거 정렬을 조문 순서에 적용하지 않았다.

## 질문한 확장 기능

이미지의 글자는 OCR을 연결하면 텍스트로 추출한 뒤 기존 변환·개인정보 정리·검토 절차에 넣을 수 있다. 현재 변환기는 PDF·HWP·HWPX·DOCX·TXT·MD 대상의 텍스트 추출이며 이미지 OCR을 지원한다고 표시하지 않는다. 이미지·스캔 문서 OCR은 설치·운영 방식과 판독 품질을 확인하는 별도 작업이다. 이번에 노트북에서 AI 학습·추론이나 OCR 성능 평가를 실행하지 않았다.

법률용어사전의 기본 기능은 AI가 필요 없다. 용어·정의·출처를 저장하고 검색하는 방식으로 구현할 수 있다. AI를 이용한 쉬운 풀이 생성은 이후 별도 확장이다. 사전 기능을 이번 수정에서 구현한 것은 아니다.

## 확인 범위

배포 빌드·정적 검사, 단위 검사 43개, 독립 PostgreSQL의 9개 조회 경로 양방향 정렬·페이징과 잘못된 정렬값 거부를 확인했다. 합성 회원으로 검색·계정·대화 화면 11곳의 서버 렌더링 응답에서 벨 위치, 검색 화면에만 존재하는 새로고침, 선택 정렬, 제목 줄임표, 동의 이력을 확인했다. 실제 화면의 위치·간격은 사용자가 직접 확인하기로 했으며 시각 검증 완료로 보고하지 않는다.
