# 설계 승인·검토 상태

기준일: 2026-11-05. 범위는 v1.2와 그 이후의 소프트 삭제 지시다. 이전 대화가 다음 작업을 v1.3이라 불렀더라도 v1.3 상세설계를 승인·완료한 것으로 기록하지 않는다.

## 승인된 방향

| 영역 | 반영할 방향 | 근거·범위 |
| --- | --- | --- |
| 공통코드 | `cmmn_cd` 자기참조 단일 계층 + `cmmn_cd_hist` | 후속 대화에서 유지된 방향. 물리 제약은 별도 |
| 코드값 | `ACT`, `PRES_DEC` 등 의미형 영문 코드 | 사용자 명시 선택 |

| 조문 번호 | 원문 문자열 보존, 자기참조 단일 조문 구조 | 기존 ADR-006·007 유지 |
| RAG | 원문·청크·임베딩·설명 분리, 원문 그대로 인용 | 기존 원문 보존 규칙 및 통합 설계 방향 |

| 사건 저장 | 사용자 확인 후 사건·사실관계 저장 | v1.2 사용자 검토 결과 |

| 문서 공유 | 한국어 중심 문서를 커밋·푸시 | 최신 사용자 요청으로 이전 Markdown 수정 보류 해제 |

## 미승인 상세설계

[DB_DESIGN.md](DB_DESIGN.md)의 테이블 목록·컬럼·타입·PK/FK·CHECK·UNIQUE·INDEX는 모두 검토용이다. 이름이 정리되어 있어도 실제 DB 구조가 확정되거나 구현된 것은 아니다.

| 검토 항목 | 승인 전에 결정할 내용 |
| --- | --- |
| 공통코드 | 코드 유일성 범위, 참조 방식, 루트/깊이, 순환 방지, 변경 제한, 이력 보관 |
| 법규·판례 | 동일성 식별, 버전·조문별 시행일, 위임·인용 관계의 시점, 원본 재수집 중복 |
| 인증·회원 | 로그인 수단, 세션·토큰·탈퇴 흐름, 비회원 1개월의 기산점·달력 계산·만료 작업 |
| 대화·인용 | 소유자 XOR, 동일 대화 부모 메시지, 유형별 인용 FK 조합, 정정 이력 |
| 사건 | 확인 UI·저장 트랜잭션, 허용 사실관계 필드·마스킹·변경이력 |
| 첨부 | 용량·형식 제한, 비공개 저장 위치, 파서·악성 파일 검사, 파싱 결과 버전 |
| 용어사전 | 표준어·동의어·쉬운 설명·출처·버전과 법규 연결 구조 |
| 알림 | 공포/시행·조문별 이벤트, 중복 방지, 채널·구독 정책 |
| 삭제·복구 | 자식 전파 범위, 권한, 활성 UNIQUE, 감사와 복구, 부분 실패 재시도 |
| 개인정보 파기 | 보유 근거·기간, 파기 대상과 방법, 백업·복제본, 법률·보안 검토 |

개인정보 파기를 별도 설계해야 한다는 점은 기록한다. 그러나 일반 업무의 `DELETE` 금지를 해제하거나 별도 파기 작업에 물리 `DELETE`를 사용할 권한까지 승인된 것은 아니다. 행 제거가 필요한 경우에는 별도 검토·승인을 받아야 한다.

## 다음 승인 경계

남은 상세설계를 검토하고 전체 물리설계를 최종 승인한 뒤에만 Prisma·마이그레이션·DB·코드 변경 작업으로 진행한다. 이 문서 변경은 그 승인을 대신하지 않는다.
