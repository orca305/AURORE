# 개인정보 보관·파기 대상 점검

2026-11-16 구현 기준. 관리자 **개인정보 보관** 화면과 `backend/tools/privacy-retention.mjs`는 보관 현황을 읽기 전용으로 집계한다. 파기 실행 기능·개인정보 탐지기·파기 완료 증명 기능은 아니다.

## 이번에 적용한 것

- PostgreSQL의 읽기 전용 반복 읽기 트랜잭션에서 건수만 반환한다. API에는 대화·사건·첨부 본문, 계정 식별자, 파일 이름, 인증 해시를 포함하지 않는다.
- 탈퇴·삭제 계정과 보관 종료·소프트 삭제된 대화에서 메시지·첨부·인용 등 연관 범위를 집계한다. 삭제된 사건·사실관계의 변경 이력도 포함한다.
- 비회원 대화의 생성일 기준 달력상 1개월 만료일과 소프트 삭제 처리 여부를 확인한다. 비회원 인증 갱신으로 대화 만료일이 연장된 것으로 간주하지 않는다.
- 학습 활용 동의는 AURORE/USER_AGR/LEARNING 이력에서 점검 시각까지의 최신 선택을 기준으로 집계한다. 같은 시각이면 이력 번호로 순서를 구분한다. 탈퇴·삭제 계정은 동의 집계에서 제외한다.
- 알려진 AURORE 임시 덤프 파일 이름 규칙으로 OS 임시 디렉터리의 일반 파일 수와 마지막 변경부터 7일이 지난 수를 확인한다. 파일 내용이나 다른 위치의 복사본은 읽지 않는다. 임시 디렉터리를 정리하지 않는다.
- 예약 백업 상태는 기존 실행기의 안전한 상태 응답만 사용한다. 백업 파일을 풀어 사용자 자료를 열람하지 않는다.

```powershell
# 저장소 루트에서 건수만 조회
node --env-file=local-dev/.env backend/tools/privacy-retention.mjs
```

CLI는 노트북 개발 DB만 허용한다. 관리자 API는 기존 관리자 역할과 유효한 세션을 요구한다. 이 화면을 여는 것으로 만료 처리·취소·파기·동의 변경을 실행하지 않는다. 집계가 실패해도 연결정보나 원문 오류를 응답에 넣지 않는다.

## 확정 정책과 현재 구현의 차이

| 확정 정책 | 현재 구현에서 확인한 상태 | 남은 작업 |
| --- | --- | --- |
| 비회원 대화는 생성일부터 1개월 보관 | 생성 시 한국 시간의 달력상 1개월 만료일을 기록하고, 만료 자료를 조회에서 제외하며 작업기가 소프트 삭제 처리 | 보관 종료 본문과 연관 자료의 실제 파기·증적 |
| 일반 업무 삭제는 소프트 삭제, 개인정보는 별도 파기 | 대화·사건·사실관계·첨부의 소프트 삭제와 접근 차단 구현 | 본문·이력·인용·인증 자료의 실제 파기 절차 |
| 첨부는 개인정보·민감정보를 정제한 Markdown만 AI에 사용 | 업로드 원본을 서버 파일로 보관하지 않고 메모리·표준 입출력으로 추출, 등록 전 사용자 확인 및 정제본 저장 | 정제 정확도·운영 로그·브라우저/OS 메모리는 별도 점검 |
| 미완료 업로드 24시간, 정제 전 자료 최대 24시간 처리 목표 | 현재 영구 업로드 대기 저장소가 없고 확인 영수증은 15분 후 만료 | 향후 대기 저장소를 추가하면 별도 만료·파기 구현 필요 |
| 학습 활용은 선택 동의, 정제·품질 확인 후 사용 | 회원가입 때 미동의 이력을 저장. 의도 분류기 학습은 별도 questions.tsv 파일 사용 | 동의 변경·철회, 자료 선별, 사본·모델 연결 추적 |
| 학습 대기 사본은 7일 | 사용자 자료 학습 대기 저장소 없음 | 구현 시 만료·철회 전파·재학습 판단 연결 |
| 본문 없는 진단 로그는 30일 | 작업 오류는 고정 분류를 쓰는 경로가 있으나, 전체 진단 파일의 30일 정리와 전수 점검은 없음 | 로그 저장 위치·내용·보관·정리 관리 |
| 백업은 7일 회전 | 관리 저장소의 예약 백업·복원 검증·성공 후 만료 묶음 정리 구현 | 임시·수동 복사본 관리, 복원 후 삭제·철회 상태 재적용 |

회원 대화·사건·정제본은 계정 이용 중 보관하는 정책을 유지한다. 활성 자료를 단순히 오래됐다는 이유로 이 집계에 파기 대상으로 넣지 않는다. 대화를 삭제했다고 사용자가 따로 확인·등록한 활성 사건 사실관계까지 자동 파기하는 기능도 추가하지 않았다.

## 집계 해석

검토 범위는 탈퇴·삭제 계정, 소프트 삭제 자료, 만료된 비회원 대화다. 해당 범위에 연결된 본문·수정 이력·첨부 인용을 별도 항목으로 집계하므로 항목을 더해 고유 사람 수나 고유 개인정보 수로 해석하면 안 된다. 내용 자체를 검사하지 않으므로 법률 질문만 있는 메시지도 본문 건수에 포함된다.

만료·철회된 회원 세션과 비회원 인증 기록은 접근할 수 없는 인증 메타데이터다. 그 기록의 존재만으로 원문 노출이나 즉시 파기 가능을 판정하지 않는다. 인증 메타데이터 보관기간과 FK·감사 이력 의존성은 실행 계획에서 별도로 검토한다. 로그인 화면의 브라우저 세션 쿠키와 서버의 최대 7일·비활동 24시간 제한도 서로 구분한다.

실제 개발 DB에서 보관 검토 범위의 본문과 인증 기록이 남아 있는 것을 확인했다. 원문이나 계정 식별자는 확인하지 않았으며, 구체적인 운영 건수는 관리자 화면과 실행 결과에서만 조회한다. 0건으로 나오더라도 파기 절차나 모든 외부 복사본 점검이 완료된 것은 아니다.

## 검증과 후속 작업

합성 자료로 탈퇴·만료·삭제에 연결된 본문·사건 이력·첨부 인용의 집계를 확인했다. 최신 동의와 철회, 미래 시각 이력 제외, 비회원 인증 갱신과 대화 만료의 독립성을 검사했다. 전후 DB 지문과 관리자 API 전후 기록을 비교해 집계가 데이터를 바꾸지 않는지 확인했다. 원문·계정·인증 해시가 응답에 섞이지 않는 것과 권한 없는 접근 차단도 검증한다.

다음은 **파기 계획·모의 실행·증적 구조**다. 대상 의존성, 원문 제거 방식, 동시 변경 검사, 백업·학습 철회 전파를 구체화해야 한다. 실제 자료 파기는 이번 점검의 실행 범위가 아니다. 외부 모델·복사본·파일 로그를 자동으로 모두 조사하거나 지웠다고 간주하지 않는다.
