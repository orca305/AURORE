# 법령 수집 중단·재개 운영 안내

2026-11-16 구현 기준. 법령의 검토 자료 수집과 DB 반영은 별도 단계다.

## 동작

- 하나의 수집 기록 폴더에는 한 프로세스만 진입한다. 실행 중인 수집의 점유를 시간 경과만으로 빼앗지 않는다.
- 날짜별 준비 완료 기록을 보존하고 실패한 날짜부터 다시 진행한다. 한 번의 실행은 최대 7일을 처리하며 첫 실패에서 멈춘다.
- `STAGED`는 검토 자료 준비 완료다. 신규 시행본·정정 자료의 DB 반영 완료를 뜻하지 않는다. 기존 검토·반영 절차를 거친다.
- 관리자 화면은 실행 상태, 점유 시작 시각, 정해진 실패 분류만 표시한다. 호스트·프로세스 번호·점유 토큰·로컬 경로·원문 오류는 전달하지 않는다.
- 새 실패 기록은 고정 오류 코드와 메시지를 사용한다. 과거 기록의 원문 오류는 파일에서 자동 삭제하지 않지만 상태 조회와 관리자 응답에서는 노출하지 않는다.

## 실행 방법

저장소 루트에서 실행한다. 아래 실행 명령은 외부 API 수집을 시작할 수 있다. `--status`만 조회 전용이다.

```powershell
# 현재 상태만 조회
node --env-file=local-dev/.env backend/tools/resume-law-refresh.mjs --status

# 최초 시작일을 지정해 준비 자료 수집 시작
node --env-file=local-dev/.env backend/tools/resume-law-refresh.mjs --from YYYYMMDD

# 기존 기록을 사용해 다음 날짜부터 계속
node --env-file=local-dev/.env backend/tools/resume-law-refresh.mjs

# 종료된 로컬 프로세스의 점유가 남았을 때 확인 후 재개
node --env-file=local-dev/.env backend/tools/resume-law-refresh.mjs --recover-lock
```

기본 종료 기준일은 한국 시간 어제다. `--through YYYYMMDD`로 범위를 줄일 수 있다. 기록 폴더를 첫 위치 인자로 지정할 수도 있으며, 같은 수집 흐름에서는 같은 폴더를 유지한다. 관리자 설정의 `AURORE_LAW_REFRESH_JOURNAL`도 같은 절대 경로여야 한다.

`--recover-lock`은 해당 기기의 이전 프로세스가 종료되었음을 확인한 경우에만 점유를 회수한다. 실행 중인 프로세스, 다른 기기의 점유, 손상된 점유 기록은 거부한다. 복구 도중 강제 종료되어 `.lock-recovery`가 남았거나 프로세스 번호가 재사용된 경우 자동 회수하지 않으므로 실행 여부와 기록을 직접 확인해야 한다. 점유 파일을 임의로 지우며 병렬 수집하지 않는다.

## 상태와 실패 분류

| 상태 | 의미 |
| --- | --- |
| IDLE | 점유 없음 |
| RUNNING | 이 기기의 수집 프로세스가 실행 중 |
| RECOVERY_REQUIRED | 이전 로컬 프로세스 종료 확인, 명시적 복구 필요 |
| OTHER_HOST | 다른 기기의 점유 확인 필요 |
| INVALID | 점유 기록 확인 필요 |

실패는 계획 작성, 원문 조회·대조, 신규 시행본 준비, 검토 목록 구성, 후보 수 초과, 보고서 불완전, 시행본 충돌, 기타 준비 실패로 구분한다. 상세 원문 오류를 표시하는 대신 해당 단계의 설정과 입력 자료를 확인한다.

## 확인 범위와 남은 작업

- 동시 실행 차단, 실제 별도 테스트 프로세스 종료 후 재개, 외부 기기·손상된 점유 회수 거부, 완료 날짜 보존, 오류 비밀정보 제외를 검사했다.
- 임시 DB에서 관리자 접근 권한과 응답의 비밀정보 제외를 확인하고, 임시 수집 기록으로 관리자 화면을 검증했다.
- 기존 법령·판례 가져오기의 중복 반영 방지와 실패 시 되돌리기 검사를 통과했다.
- 이번 작업에서 실제 외부 API 수집·법령 반영·예약 실행 등록은 하지 않았다. 새 테이블이나 마이그레이션도 추가하지 않았다.
- 후속 작업으로 [판례 목록 기반 수집·재개와 명시적 반영](PRECEDENT_COLLECTION.md)을 추가했다. 판례 신규 발견·날짜별 자동 목록 생성은 아직 구현하지 않았다.
- 파일 점유는 현재 단일 PC 베타 운영 기준이다. 여러 서버에서 실행할 때에는 공유 저장소의 파일 연산 보장을 확인하거나 중앙 작업 점유 방식으로 전환한다.
