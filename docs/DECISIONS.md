# 설계 결정

## 원문을 따로 보관한다

법제처 응답을 가공 전 상태로 DB에 남기고, 파싱 결과와 검색용 데이터는 여기서 다시 만들 수 있게 했습니다. 답변이 인용한 시점의 원문을 나중에도 확인할 수 있어야 하기 때문입니다.

## 조문 번호를 숫자로 바꾸지 않는다

가지번호, 원문자, 한글 목 번호처럼 법령마다 표기가 달라서 문자열로 보존합니다. 조·항·호별 테이블을 만들지 않고 하나의 계층으로 둔 것도 같은 이유입니다.

## 지우지 않고 표시한다

업무상 삭제는 삭제 표시로 처리합니다. 인용과 이력이 끊기지 않게 하려는 것입니다. 개인정보 파기는 따로 설계해야 합니다.

## 사건은 확인한 것만 저장한다

AI가 읽어 낸 내용을 바로 사실로 저장하지 않습니다. 대화의 첫 질문을 개요로 자동 저장하는 것은 맥락을 잇기 위한 것이고, 확인된 사실로 취급하지 않습니다.

## 후보 중에서 고르기보다 답을 쓰고 검증한다

처음에는 검색한 조문 가운데 맞는 것을 모델이 고르게 했습니다. 처음 보는 질문에서 답을 못 내는 경우가 많았습니다. 지금은 모델이 답을 쓰되, 근거를 확인한 항목에만 조문을 표시하고 원문에 없는 내용은 코드로 걸러 냅니다.

## 답변 모델은 Claude Haiku, 대체는 로컬

같은 50문항에서 Haiku와 Sonnet의 통과 수가 같았고 Haiku가 더 빨라 Haiku를 선택했습니다. 비용이나 장애에 대비해 로컬 모델로 자동 전환합니다. API 키가 없으면 처음부터 로컬만 씁니다.

## 첨부 문서는 확인한 변환 글만 보낸다

파일을 그대로 모델에 넘기지 않습니다. 사용자가 변환된 글을 보고 고친 뒤 등록한 것만 사용합니다.

## 외부 공개는 접속 코드로 제한한다

법률 검토를 마치지 않은 상태라, 터널로 공개하더라도 코드를 아는 사람만 들어올 수 있게 했습니다.
