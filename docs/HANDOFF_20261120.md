## 오늘 한 일

자세한 수치와 근거는 [근거 기반 쉬운 해설 연결](GROUNDED_EXPLANATION_20261120.md)에 있다.

1. **쉬운 해설 단계 연결**: 검색 → 관련성 검토 → 원문 인용 뒤에 `/legal/explain`(`ai-server/legal_explain.py`)을 호출한다. 근거 구간 일치, 원문에 없는 숫자·조문 금지, 단정 표현 금지, 단서 설명 필수를 결정적으로 검사하고 별도 모델 검토를 거친다. 하나라도 실패하면 기존 고정 문구로 되돌아간다. 화면에는 "AI 쉬운 해설 · 참고용" 표시를 붙이고 원문 인용은 따로 둔다.
2. **검색어 힌트·순위**: `/intent/analyze` 키워드(최대 5개)를 검색어와 순위 가중치로만 쓴다(차단·인용 기준 아님). 후속 질문은 앞선 질문을 미확정 문맥으로만 전달하고 저장하지 않는다.
3. **마스킹**: 해설·관련성 검토 모델로 나가는 질문·문맥은 항상 패턴 마스킹(`redactDocument`)을 거친다. 서술 속 이름·주소는 가려지지 않는다.
4. **외부 모델 선택 옵션(기본 꺼짐)**: Claude Haiku(`claude-haiku-5-5`)를 해설과 관련성 검토에 쓸 수 있다. **기본은 로컬 e4b이며 사용자가 로컬 유지를 결정했다.** 외부 전송 정책(동의 문구)이 미결정이라 실사용자에게 켜지 않는다.
5. **평가 도구와 비교**: `backend/tools/evaluate-explanations.mjs`(합성 질문 34개). 로컬 검토 23/34, Haiku 검토는 구성에 따라 21~23/34로 어느 쪽도 확실히 낫지 않았다.
6. **법령 우선 수집 목록**: `backend/tools/priority-law-titles.txt`와 `collect-selected-laws.mjs`의 `LAW_TITLES_FILE` 입력(법령별 실패 건너뛰기).

## 데스크탑에서 할 일 (순서대로)

1. 저장소에서 미커밋 변경을 확인한 뒤 최신 main을 받는다.

```powershell

```

```powershell
git pull --ff-only origin main
```

2. AI 서버를 재시작한다(새 코드: `/legal/explain`, 문서 검토 로그 등). 재시작 뒤 `/openapi.json`에 `/legal/explain`이 보이는지 확인한다. 로컬이 기본이므로 `AURORE_EXPLAIN_PROVIDER`·`AURORE_DOCUMENTS_PROVIDER`·`ANTHROPIC_API_KEY`는 설정하지 않는다.
3. **로컬 e4b 해설 실측**: 평가 도구를 데스크탑에서 실행한다(백엔드 `pnpm build` 선행, 결과 파일은 새 이름으로).

```powershell
node --env-file=local-dev/.env --use-system-ca backend/tools/evaluate-explanations.mjs backend/.eval-results/desktop-20261120/local-explain.json 2026-11-20
```

   확인할 값: `explained`/`evidenceFound`(해설 성공률), `fallbackRate`, 평균·P95 시간, `wrongCitation`, `overreach`. 해설이 너무 자주 폴백하면 `legal_explain.py`의 검사 거부 코드(`legal_explain_rejected …` 로그)를 보고 어떤 검사가 원인인지 먼저 구분한다.
4. **법령 수집 확대**(법제처 인증값 `MOLEG_OC`와 DB 5433이 필요하므로 데스크탑에서만 가능). DB 초기화 없이 추가 적재한다. 법령명이 현행 명칭과 다르면 해당 줄만 SKIPPED로 남으니 결과를 보고 `priority-law-titles.txt`를 고친다.

```powershell

```

```powershell

```

5. 수집 뒤 같은 34개를 다시 측정해 비교한다. `evaluate-explanations.mjs`의 시나리오는 "DB에 법령이 있는 질문"과 "없는 질문"을 구분하므로, 수집한 법령(산재·고용보험·약관·교통 등)의 질문은 기대 법령명을 넣어 갱신해야 한다(`out-` 시나리오의 `null`을 해당 법령명으로).

## 이후 개발 순서 (제안)

1. 로컬 관련성 검토의 거절 원인 확인: 추출 단계(`extracted=0`)인지 검토 단계(`approved=0`)인지 로그로 구분한다.
2. 로컬과 외부 두 검토가 모두 승인할 때만 쓰는 결합 방식은 정확성이 오르지만 찾는 수가 줄 수 있다. 외부 전송 정책이 정해진 뒤 검토한다.
3. 상가/주택, 개인/기업처럼 질문 단서와 인용 법령 종류가 어긋나는 사례(예: "가게 월세"에 주택임대차보호법)를 줄이는 확인 단계.
4. 대표 시나리오 3~5개의 화면 시연과 스크린샷(앱 기동 후). 면접 시연 우선순위는 근거 기반 쉬운 해설, 안정적인 시작·실패 안내, 구조도·평가·한계 설명이다.
5. 외부 AI를 실사용자에게 쓰려면 먼저 동의 문구에 외부 전송 포함 여부, 마스킹 범위, 사업자의 학습·보관 정책을 정한다.

## 환경 설정 참고

| 환경변수 | 효과 | 기본 |
| --- | --- | --- |
| `AURORE_EXPLAIN=0` | 쉬운 해설 끔(고정 문구) | 켜짐 |
| `AURORE_SEARCH_HINTS=0` | 검색어 힌트 끔 | 켜짐 |
| `AURORE_EXPLAIN_PROVIDER=anthropic` | 해설을 Haiku로(키 필요) | 로컬 |
| `AURORE_DOCUMENTS_PROVIDER=anthropic` | 관련성 검토를 Haiku로(키 필요) | 로컬 |
| `AURORE_REVIEW_STRICT=0` | 외부 검토의 엄격 기준 끔 | 엄격 |
| `AURORE_EXPLAIN_URL`, `AURORE_REVIEW_URL` | 해설·검토만 다른 로컬 AI 서버로(루프백만 허용) | 없음 |

`ANTHROPIC_API_KEY`는 환경변수로만 읽는다. Git 제외 파일(`local-dev/.env*`)에만 둔다.
