## 코드 변경

### 1차 입력 필터

NestJS가 질문을 저장하고 AI 작업을 만들기 전에 빈 입력·1,000자 초과·정규화 후 길이 초과·제어문자·기호만 있는 입력·동일 문자만 8회 이상 반복된 입력을 거부한다. 해고·이혼·사기·상속·보증금 같은 짧은 법률 용어와 일상적인 상황 설명은 통과시킨다. 의미가 모호하다는 이유로 1차에서 차단하지 않는다.

진입점이 NestJS이므로 서버 안에서 바로 검사한다. Python에 별도 필터 HTTP 호출을 추가하지 않았다. 검사에만 정규화를 사용하고 저장할 원문과 기존 요청 지문은 기존처럼 앞뒤 공백만 제거해 보존한다. 잘못된 질문이 작업/대화 저장 트랜잭션에 진입하지 않는 검사도 추가했다. 인증 단계의 DB 조회까지 생략한다는 의미는 아니다.

### 로컬 LLM 의도 분석

기존 Ollama와 Gemma 4 E4B 별칭 aurore-local:e4b가 이미 설치돼 있었다. 재다운로드하지 않았다. 실제 모델 정보는 gemma4 / 7.5B / Q4_K_M이며 제품 이름 E4B와 총 파라미터 표기는 구분한다.

새 POST /intent/analyze는 LEGAL/NON_LEGAL/UNCERTAIN, 분야, 최대 5개 검색 키워드, 검색 필요 여부를 엄격한 JSON 스키마로 반환한다. 법률 해설을 생성하지 않고 확률로 오해할 confidence를 반환하지 않는다. 타임아웃·잘못된 구조·모순된 검색 여부는 UNCERTAIN + 검색 유지 + available=false로 처리한다. 질의나 사용자 자료를 학습·수집하지 않는다.

새 분석 API의 routingEnabled는 항상 false다. 기존 CPU 분류 API와 평가 게이트, AURORE_INTENT_CLASSIFY=0 및 AURORE_INTENT_ENABLE_ROUTING=0은 유지했다. 기존 API 계약을 바꾸거나 새 모델로 일반 사용자의 검색을 자동 차단하지 않았다.

### 원문 검색 보완

실제 법령으로 검사했을 때 조문 제목만 조문내용에 있고 실제 규정은 항내용에 있는 자료에서 제목만 전달되는 문제가 있었다. 본문 필드가 있으면 제목만 있는 필드를 제외하고, 조문 지정 질문은 최대 3개의 원문 필드를 후보로 전달하도록 수정했다. 서로 다른 필드를 임의로 이어 붙인 문장을 인용하지 않는다. 원문 해시·출처·시행일·정정·소프트 삭제 검사는 유지한다. 월급/급여를 임금으로 찾는 검색 동의어도 추가했다.

분류 키워드를 검색 힌트로 쓰는 연결은 평가 도구에서 실제 DB/AI로 확인했다. 생성된 힌트를 인용 근거나 확인된 사용자 사실로 저장하지 않는다. 운영 경로의 새 분류 자동 분기는 아직 활성화하지 않았다.

## 실행 중 서버와 남은 반영

실제 모델 평가는 루프백 테스트 서버 127.0.0.1:8002에서 수행했다. 기존 8001 AI 서버 재시작 명령은 실행 정책이 차단했다. 이 제한을 다른 종료 방법으로 우회하지 않았다. 기존 8001/3001 실행 프로세스는 유지했고, DB의 추가 법령 목록은 기존 서버에서도 보인다. 새 Python 라우터와 백엔드 필터/검색 변경은 실행 중인 서버가 재시작될 때 반영된다. 빌드 성공을 서버 반영 완료로 설명하지 않는다.

재시작 시 기존 local-dev/start-ai.cmd로 8001 AI를 시작하고, 백엔드는 local-dev/.env를 읽어 빌드된 dist/main.js를 실행한다. 새 분류 기능은 그 후에도 평가 전용이며 자동 분기는 비활성이다. 테스트 서버 8002는 회사 노트북 SSH 허용 목적지에 추가하지 않았다.

재현 예시(평가 서버 실행 후 저장소 루트에서, 기존 결과를 덮어쓰지 않는 새 파일명 사용):

```powershell
ai-server/.venv/Scripts/python.exe ai-server/intent_lab/evaluate_local_llm.py --url http://127.0.0.1:8002 --out backend/.eval-results/local-ai-20261119/intent-new.json
$env:AURORE_AI_URL='http://127.0.0.1:8002'
node --env-file=local-dev/.env --use-system-ca backend/tools/evaluate-local-rag.mjs backend/.eval-results/local-ai-20261119/rag-new.json 2026-11-19
$env:AURORE_PG_CONTAINER='aurore-desktop-postgres'
node --env-file=local-dev/.env --use-system-ca --test backend/tools/chat-storage.test.mjs backend/tools/stored-evidence.test.mjs
```

다음 우선순위는 실행 서버 반영, 의도 분류의 독립 문맥/다회 평가, 일상 표현 검색·관련성 검토의 안정성 개선, 전체 법령의 재개 가능한 수집 확장이다. 판례 이력·행정규칙·자치법규는 전용 파서와 저장 검증 후 확장한다. 원문 정의나 법률용어 초안은 자동 변경/게시하지 않았다.
