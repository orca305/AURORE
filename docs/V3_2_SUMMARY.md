# AURORE v3.2 — 설계 결정 및 작업 정리

기준일: 2026-11-05. 근거: 대화 「법령 해설 프로그램 개발환경 세팅」(`6aa81388-db70-83e9-857e-a0d811879d82`)에서 읽기 도구로 확인한 v2.8 검토 결과부터 오늘 커밋 요청까지. 더 오래된 세부 합의는 기존 문서에서 확인한 범위만 유지한다. 이 문서는 새 법률·보안 검증 결과가 아니라 대화의 결정 기록이다.

## 확정된 진행 방향

| 항목 | 결정과 범위 |
| --- | --- |
| v3.2 전환 | 전체 40개 테이블의 설계 검토를 마무리한 것으로 간주하고 구현 준비로 넘어간다. 남은 세부 구조는 실제 구현 과정에서 보완한다. |
| 검증 상태 | v3.0 공통코드 2개, v3.1 회원·인증 6개의 상세설계가 대화에 제시되었다. 나머지 32개의 동일 수준 검토나 40개 테이블의 SQL 실행 검증이 완료된 것은 아니다. |
| 구현 권한 | DB·Prisma 스키마·마이그레이션·애플리케이션 변경은 최종 미승인이다. 이번 요청은 문서 정리와 Git 커밋만 승인한 것으로 해석한다. |
| 구현 방식 | 기존 프로젝트를 우선 분석·재사용하고 핵심 기능부터 단계적으로 구현·출시한다. 트리거는 기본적으로 사용하지 않고 필요 시 별도 검토한다. |
| 보존기간 | 데이터 유형별 목적·기간을 나눈다. 비회원 대화는 생성일로부터 1개월이며 인증 세션 만료와 분리한다. 다른 데이터의 보존기간은 미결정이다. |
| AI 이용량 | 비회원 일 5회·회원 일 20회를 테스트 시작값으로 사용한다. 영구 운영 한도로 확정하지 않는다. |
| AI 예산 | 기존 `ai_job`에 예약액을 기록하고 원자적으로 예약·정산하는 방식을 사용한다(v2.9 사용자 선택). |
| 관리자 원문 열람 | 승인·취소·동시성 검증을 완료하기 전까지 비활성화한다(v2.9 사용자 선택). |
| 승인 절차 | v2.9의 영역별 완전 명세 검토 후 승인 방향에서, v3.2는 반복적인 전체 테이블 검토를 종료하고 구현 준비로 전환했다. 실제 구현 승인은 여전히 별도다. |

## 상세설계로 제시된 사항 — 구현 확정과 구분

- 공통코드: `cmmn_cd` 단일 계층과 `cmmn_cd_hist`. v3.0 제안은 `AURORE` 루트, ROOT/GROUP/CATEGORY/VALUE, 형제 간 코드 유일성, 코드·부모·유형 불변, NestJS 트랜잭션 이력이다. 그룹 간 같은 코드가 가능하므로 경로로 식별하는 전제다. DDL·Prisma·권한·시드·동시성 검증은 아직 실행하지 않았다.
- 회원·인증: `app_user`, `user_auth`, `user_sess`, `guest_sess`, `user_agr_yn_hist`, `user_stat_hist` 6개 초안. ID·비밀번호 가입, 선택 이메일·닉네임, 비밀번호 해시와 세션 토큰 해시 분리, 비회원도 임의 인증 토큰 사용, 동의·계정 상태 이력 기록을 제시했다.
- 사건·첨부·북마크·개인 알림은 회원 전용이며 비회원은 채팅 범위다. 사건·사실관계는 사용자 확인 후 저장하고 조회·연결·수정마다 소유권을 검증한다.
- 법규·버전·조문, 공식 원문·검색 자료·AI 설명 분리 및 문자열 조문 번호 보존 방향을 유지한다. 공식 API 원본의 초기 저장 위치는 PostgreSQL `src_snapshot`이다.
- 일반 업무는 소프트 삭제다. 개인정보 파기는 별도 절차로 원본·이력·파싱 결과·인용·임베딩·복사본·백업까지 검토한다. 대화의 전용 파기 예외 언급을 실제 물리 삭제 권한으로 해석하지 않으며, 현재 저장소 규칙에 따른 별도 검토·승인이 필요하다.

## 계속 관리할 미결정·검증 과제

- 로그인 ID 문자·길이·정규화, 계정 복구 방식, 탈퇴 ID 영구 재사용 금지의 적법한 보존 근거와 기간. `login_id_fpr` 도입은 보류한다.
- 회원 세션 7일·비회원 인증 24시간은 제안값이다. 비활동 만료·비회원 재인증·복구와 달력상 1개월 계산·파기 일정도 확정이 필요하다.
- 유형별 개인정보 보존·외부 AI 전송 정책, 약관·동의문 버전 재현, 파기 순서와 FK 충돌 해결.
- 질문 횟수의 일자·실패·재시도·복원 규칙, 멱등성, 전체 예산 잠금·예약 해제·과금 불확실성 처리.
- 인용 구간과 메시지 일치, 사실관계 출처와 사건 소유자 일치, 선택적 복합 FK의 NULL 조합, 활성 UNIQUE, 법령 적용 시점·정정 이벤트 검증.
- 관리자 승인·취소·열람 동시성 및 외부 파일 접근 취소 검증. 구체 컬럼·제약·잠금 방식은 검증 전 설계안이다.

## 실제 저장소 확인 결과

확인 위치는 로컬 `easy-law-ai`, 브랜치는 `main`, 원격 주소는 `https://github.com/orca305/AURORE.git`이다. 작업 시작 HEAD는 `eb3f95e`이며 추적·스테이징·미추적 미커밋 변경은 모두 없었다. 따라서 이번에 생성·수정한 문서만 커밋 대상으로 삼는다.

| 확인 대상 | 저장소에서 확인한 상태 |
| --- | --- |
| 문서 | 기존 기준은 v1.2 및 후속 삭제 정책으로, 대화의 v3.2와 차이가 있었다. 기존 초안은 과거 자료로 보존한다. |
| 프런트엔드 | `frontend/package.json`: Next.js 16.3.5, React 19.2.8 선언 |
| 백엔드 | `backend/package.json`: NestJS ^12.0.1, Prisma 및 Client 7.10.0 선언 |
| AI 서버 | `ai-server/requirements.txt`: FastAPI 0.141.1, Uvicorn 0.53.0 선언 |
| Prisma | `backend/prisma/schema.prisma`는 PostgreSQL 및 `Law` → `laws` 모델 1개다. 40개 테이블 설계가 반영된 상태가 아니다. |
| 마이그레이션 | 추적된 SQL은 `20260921044321_init_law/migration.sql`이다. 실제 DB 적용 이력과 동일하다고 단정하지 않는다. |

버전은 파일에 선언된 값이며 실행 환경의 설치·기동을 확인한 결과는 아니다. 실제 PostgreSQL 접속, 데이터 조회·변경, 마이그레이션 실행은 하지 않았다. 비밀정보 파일의 내용을 수집하거나 문서에 옮기지 않았다.

## 다음 작업

v3.3은 기존 구현과 설계의 차이, 권장 구조·실행 방법, 1단계 테이블·API 범위, 기존 데이터 보존 및 마이그레이션 순서, 최초 통합 테스트 기준을 읽기 중심으로 정리한다. 구현 순서는 환경·공통코드·인증 → 법령 수집·검색 → RAG 채팅 → 사건·문서 → 용어·관심 법령·알림 → 통합 검증·출시다. 개인정보 보호와 접근 통제는 각 기능 구현 시 함께 적용한다. 이번 문서 커밋은 해당 구현의 착수를 승인하지 않는다.
