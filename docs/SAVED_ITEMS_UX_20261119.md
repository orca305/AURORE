# 알림·관심 항목의 상태와 실패 안내 개선

2026-11-19. 데스크탑 연결을 보류한 상태에서 노트북의 일반 기능을 개발했다. 실제 읽음 상태·관심 등록·DB 행·스키마·모델은 변경하지 않았다.

## 알림

- 모두 읽음은 처리 범위를 확인한 뒤 실행한다. 현재 필터 밖의 다른 종류도 포함됨을 안내한다. 기존 서버의 readThroughId 이하 처리 정책을 유지하며 새 기준 번호가 화면에 들어오면 확인 상태를 초기화한다. 서버 정책을 무조건 전체 읽음으로 바꾸지 않는다.
- 읽음 응답이 read=true인지 확인한 뒤 목록/벨 갱신을 알린다. 불확실한 결과와 전송 예외는 완료로 안내하지 않고 현재 알림을 다시 확인하도록 한다.
- 미확인 개수를 읽지 못하면 0개로 표시하지 않고 벨에 확인 불가 상태를 구분한다. 이후 정상 조회가 되면 실제 개수로 복구한다.
- 필터 결과 없음과 빈 후속 페이지를 구분한다. 후속 페이지는 현재 필터/정렬/조회 개수를 유지한 처음 페이지 링크를 제공한다. 새 알림 동기화가 지연돼도 유효한 기존 알림은 보여준다.

## 관심 항목

- 변경 응답의 종류·대상 ID·저장 값이 요청과 일치하는지 확인한다. 결과를 모르면 상태 확인 필요로 표시하고 추가 토글을 막은 뒤 현재 상태 재조회로 안내한다.
- 법령/판례 검색의 간단 별표를 유지한다. 관심 목록의 일반 버튼은 ‘관심 해제’처럼 수행할 동작을 명시한다. 별표 상태를 읽지 못했을 때 미등록이라고 단정하지 않는다.
- 상태 조회 응답의 저장 ID가 요청한 대상 안에 있는지 검사한다. 실패/잘못된 응답은 새로고침으로 확인한다.
- 검색 조건·정렬·10/20/50 조회를 유지한다. 검색 결과 없음과 범위를 넘은 빈 페이지를 구분하고 처음 페이지로 돌아갈 수 있게 한다.

## 공통 응답 경계

ID의 BIGINT 범위·목록 건수·날짜·종류·이동 경로를 검증한다. 법령/판례의 서비스 내부 조회 경로만 링크로 표시한다. 잘못된 목록 응답은 빈 목록이나 완료로 대신 표시하지 않는다. 입력/응답 원문·인증정보를 오류 안내로 복사하지 않는다.

## 검증과 한계

프런트 빌드·정적 검사 통과. Node 검사 7개 통과: 새 목록/영수증 경계 3개, 알림/관심 화면 서버 응답 1개, 공통 헤더를 사용하는 회원·사건 회귀 3개다. 임시 응답 서버의 GET만 사용했다. 필터 전달·빈 페이지 복구·모두 읽음 초기 확인 버튼·동기화 지연 안내·개수 확인 불가·잘못된 응답을 확인했다.

실제 읽음 POST/관심 PUT, 브라우저에서 확인을 펼치고 누르는 상호작용·별표 갱신·벨 주기 갱신, 데스크탑 실제 데이터와 경쟁 요청은 연결 후 확인할 범위다. 이번 검사를 실제 사용자 데이터 처리 완료로 표시하지 않는다. 화면 위치·색상은 사용자 확인 범위다.
