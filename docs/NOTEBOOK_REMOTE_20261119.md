# 노트북에서 데스크탑 DB·로컬 AI 사용

2026-11-19. 실제 데이터와 모델은 집 데스크탑 D드라이브에 유지한다. 노트북에서는 앱만 실행하고 SSH로 데스크탑 DB와 Python AI를 사용한다. D드라이브를 노트북에 마운트하거나 Ollama·Python AI·별도 DB를 설치하는 단계는 없다.

## 준비와 실행

1. 집 데스크탑에서 기존 local-dev/start-desktop.cmd로 서비스를 준비한다. 데이터 위치는 D:/DATA/DockerDesktopWSL, 원문은 D:/DATA/snapshots다. 외부 주소/DDNS와 공유기 전달 설정은 [데스크탑 연결 문서](DESKTOP_RESUME_20261119.md)를 따른다.
2. 노트북에서 기존 local-dev/connect-desktop.ps1 -HomeAddress <공인IP또는DDNS>를 실행한다. 서버 지문을 기존 문서와 비교하고 터널 창을 열어 둔다. SSH 개인키·DB 암호를 대화나 Git에 넣지 않는다.
3. local-dev/.env.notebook.example을 local-dev/.env.notebook으로 복사하고 데스크탑의 DB 계정·암호를 로컬에서 입력한다. 이 전용 설정은 Git에서 제외한다. 기존 local-dev/.env는 변경하지 않는다. DB 주소는 127.0.0.1:15433, AI는 http://127.0.0.1:18001, 백엔드는 http://127.0.0.1:3001로 둔다.
4. 저장소 루트에서 연결만 먼저 확인하려면 아래 명령을 실행한다. 결과에 암호나 질문 본문은 출력하지 않는다.

```powershell
node --env-file=local-dev/.env.notebook local-dev/check-notebook.mjs
```

5. backend/frontend 의존성은 각 폴더에서 pnpm install --frozen-lockfile로 준비한다. 이후 local-dev/start-notebook.cmd를 실행한다. 연결 확인 후 Prisma 클라이언트 생성과 앱 빌드를 수행하고 노트북의 3001/3000을 루프백으로 시작한다. 최신 빌드를 이미 검증했다면 start-notebook.ps1 -SkipBuild로 빌드를 생략할 수 있다.

기동 도구는 DB 마이그레이션·수집·학습·모델 추론을 수행하지 않는다. DB·AI 점검 실패 시 앱을 시작하지 않는다. 3000/3001이 이미 사용 중이면 기존 프로세스를 자동 종료하거나 재사용하지 않고 알려준다. 실행한 PID와 Git 제외 local-dev/runtime 로그 위치를 표시한다.

## 점검 범위

- DB: SSH 전용 포트·DB 이름·PostgreSQL 17 확인. READ ONLY 트랜잭션으로 마이그레이션 일치와 법령/시행본/조문 수만 조회한다. 변경 명령과 개인정보 본문 조회는 없다. 스키마가 다르면 자동 수정하지 않는다.
- AI: /health의 AURORE 서비스 식별과 /documents/health의 모델 등록 상태를 확인한다. 이 과정은 추론을 실행하지 않으며 실제 GPU 사용·답변 정확도·속도 평가를 대신하지 않는다.
- 노트북 의도 분류 자동 호출은 0으로 유지한다. 실제 질문의 법률 근거 추출이 필요하면 요청은 터널 너머 데스크탑 AI에서 처리된다.
- 저장 원문 RAG는 DB의 src_snapshot 내용을 사용하므로 기본 법령 근거 조회에 D드라이브 공유 폴더가 필요하지 않다. 대량 수집·정정 검토 원본 파일 등 데스크탑 전용 운영 작업은 데스크탑에서 수행한다. 파일 경로가 필요한 모든 운영 기능까지 원격 사용 가능하다고 보장하지 않는다.
- 노트북과 데스크탑 앱이 같은 DB를 사용한다. 실제 계정·대화 작업은 공용 DB에 반영된다. 개발 통합 테스트는 별도 검증 DB를 사용해야 한다.

## 현재 확인한 범위와 다음

이번 노트북에서는 15433/18001 SSH 전달 포트가 열려 있지 않았고 기존 local-dev/.env는 노트북 5433을 가리켰다. 기존 설정·DB·데스크탑 파일은 수정하지 않았다. 실제 .env.notebook도 비밀값 없이 임의 생성하지 않았다. 외부 주소/DDNS를 받으면 터널 연결·실제 DB 수량·AI 준비 상태·앱 요청까지 확인한다. 데이터 85개 등 기존 수치는 데스크탑 인계 당시 기록이며 오늘 원격 실측값이 아니다.

검증 결과: 원격 연결 점검 도구 5개, 기존 서버 단위 51개 통과. 프런트·백엔드 빌드와 PowerShell 구문 검사 통과. 백엔드 정적 검사의 기존 경고 10개 유지. SSH 미연결 시 DB·AI 상태를 분리하여 보고하고 인증정보를 출력하지 않는 실제 실패 경로를 확인했다. 현재 노트북 SSH 설정 및 알려진 호스트의 공개 서버 지문 기록에도 집 데스크탑 주소는 없었다. 실제 데스크탑 연결·앱 기동은 아직 확인하지 못했다.

## DDNS 등록 후 실제 외부 연결 확인

사용자가 등록한 aurore-home.iptime.org가 정상 해석되고 TCP 40222가 응답했다. 공개 ED25519 지문을 이전 데스크탑 기록과 대조해 일치를 확인한 뒤 기존 SSH 개인키로 aurore_tunnel 연결을 열었다. DDNS 관리 계정과 암호는 SSH 인증에 사용하거나 저장하지 않았다. 확인한 서버 키는 사용자 비공개 AURORE/ssh 영역에 별도로 두고 엄격한 키 검사를 사용했다.

- 노트북 18001의 /health와 /documents/health: AURORE AI 서비스 및 등록 모델 준비 상태 정상. 모델 추론은 실행하지 않았다.
- 노트북 15433의 PostgreSQL: 서버까지 연결됐으나 기존 노트북 DB 인증값은 28P01 인증 실패였다. DB 개수·자료는 아직 읽지 못했으며 기존 수치를 오늘 원격 실측값으로 바꾸지 않는다.
- Git 제외 local-dev/.env.notebook을 준비했다. DB 암호는 자리표시자로 남겼고 데스크탑과 같은 DB 암호를 사용자가 로컬에서 입력한 뒤 재확인한다. DDNS 관리 암호를 DB 암호로 추정하거나 시도하지 않았다.
- DB·AI 전체 준비 확인 전이므로 앱을 시작하지 않았다. 데이터·스키마·학습 상태 변경은 없다. 현재 터널은 사용 중 유지해야 하며 노트북/데스크탑 재시작 후에는 다시 연결한다.

후속 인증 확인: 기존 노트북 설정의 비밀번호 필드끼리는 일치했으나 데스크탑 DB는 인증을 거부했다. 사용자가 별도로 1회 사용을 승인한 값도 28P01로 거부됐다. 추가 추측/재설정은 수행하지 않았으며 실제 값은 문서·Git에 기록하지 않았다. 노트북 전용 설정의 자리표시자를 유지했다. 다음은 데스크탑 프로젝트의 실제 DB 인증 설정 확인이다.
